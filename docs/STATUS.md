## P2-06 关闭结论

五组独立采集使用同一冻结任务和诊断墙，每组横向 680 + 纵向 660，共 1,340 帧。第 2、3、4
组用于推导门限，第 5 组在门限提交后采集、只用于独立检验；第 1 组因缺少渲染工况记录只作
旁证。五组冻结巡检域内 21 个 feature 均零漏拍。

| 指标 | 冻结门限 | 第 5 组检验 |
| --- | ---: | ---: |
| 巡检域内 feature 漏拍 | `= 0` | `0` |
| 绝对锚点偏差 P95 | `≤ 2.5 mm` | `1.130 mm` |
| 局部残差 P95 | `≤ 0.5 mm` | `0.143 mm` |
| 尺度误差绝对值 | `≤ 50 ppm` | `16.2 ppm` |
| 航向误差绝对值 | `≤ 0.01°` | `0.0002°` |
| 接缝 / off-seam P95 | `≤ 5.0` | `3.50` |
| optimized 不劣于 pose-only | 必须成立 | 通过 |

人工已浏览第 1 组的 170 个全分辨率 tile，未发现重影、拖影或“几何覆盖但视觉错误”。
第 5 组另有 170 个已逐个哈希验证的原尺寸 tile。2026-09-27 用户报告已快速浏览基本
全组，未见明显问题；这属于快速目视筛查，**不是逐张原尺寸细节复核**，后者仍待完成。
该组七项数值独立检验已通过，不能据此冒称视觉独立复核完成。域外约 43 万
feature 像素按产品定义不作门禁要求；这不表示它们物理上不可拍到。完整的巡检域、足迹分类、
门限来源、已知 `+21 ppm` 尺度偏置和适用范围见[拼接设计](MOSAIC_PLAN.md)，可引用结果见

## 最近关闭的可靠性与光度问题

- **大图偶发等待**：根因是 Fast DDS 默认共享内存段无法容纳一帧全部分片。三个大图发布者
  已使用 64 MiB profile；46,300 次压测零慢捕获，完整纵向任务 `660/660`。分层证据与以后
  的诊断规则见[长任务时序稳定性](LOCALIZATION_GAP_PLAN.md)。
- **平场欠校正**：旧灰板与诊断墙使用不同 Gazebo 着色路径。标定靶现与被摄墙使用相同 PBR
  材质、同一表面和均匀 albedo；新 30 帧标定使角/中心从 `0.907` 改善到 `1.011`，同一输入
  的 optimized 接缝 P95 从 `7` 降到 `6 DN`，几何指标未退化。以后新数据使用
  `flat_field_sim_pbr_exp065_20260901.npz`，其文件名与 SHA-256 已记录在
  `climbot_image_processing/config/inspection_flat_field.yaml`；SHA-256 对不上就拒绝处理，
  少给或给错都必须显式覆盖；既有正式摘要保留其原始标定 provenance，不改写。
  排查中被否定的两条也记在世界模型里，免得后人重走：旧灰板重拍与 2026-08-25 的存档
  逐点重合（角/中心 `0.673` vs `0.672`），标定并未过期，错的是靶面材质；把靶从
  `0.059 m` 挪到被摄平面只让角/中心从 `0.673` 变到 `0.668`，站位只值半个点。反过来，
  只换 PBR 路径而不带 `albedo_map` 比原来的经典材质更差——角/中心 `0.709`，并因 PBR
  镜面项引入 `0.737` / `0.839` 的左右不对称。起作用的是 albedo 贴图本身。
- **高并发测试竞态**：此前 `-j8` 暴露的失败均按真实缺陷修复并补回归；默认保持 8 并发，
  不以降低并发或重跑通过掩盖低频失败。2026-10-17 S0 审计修复测试夹具的时钟代次、失败
  清理和管理器 Action 发现问题，并加确定性回归；完整 `-j8` 连续 8 轮各为 1,436 tests、
  0 errors／0 failures／67 skipped。后续已受控复现并修复输入时间戳错配引起的同类超速，
  正常／延迟输入峰值均约 `0.200 m/s`，原 `0.205 m/s` 门槛不变；并补齐 Start 拒绝日志。
  最终完整 -j8 两轮各 1555 tests、0 errors／0 failures／74 skipped。原次逐包时序未留存，
  不追认唯一原因；修复与证据边界见[时戳专项](../results/cruise_timestamp_2026-10-17/REPORT.md)。

## 当前性能专项

离线 hard-cut CUDA fusion 已完成实现与开发树验收，合同见
[GPU 加速计划](GPU_ACCELERATION_PLAN.md)。同一 1,340 帧 P2-06 三轮交替 A/B 中，fusion
中位数从 CPU `91.86 s` 降到 CUDA `47.73 s`（`1.92×`），命令全程从 `108.01 s` 降到
`64.02 s`（`1.69×`）。coverage、owner 和接缝逐位一致，灰度最大差 `1 DN`；诊断墙仍为
巡检域内零漏拍、optimized 锚点 P95 `1.13 mm`、接缝 P95 `7 DN`。默认保持 CPU；装有匹配
Toolkit/GPU 的机器可显式选 `cuda`，`auto` 只对 CUDA 可用性或执行故障回退。
本项目 CUDA 开发机后续完整拼接、性能和验收测试统一显式传 `--backend cuda` 并核对 manifest
的 effective backend；CPU 仅用于有意的基线/A-B，`auto` 不作为 GPU 证据。

P1 CUDA 原型和连续坐标 fusion 都已撤回：前者端到端不比 8-worker CPU 快，后者不改善验收
等级却改变 hard-cut owner。当前没有保留“能运行但没有实际收益”的 GPU 分支。
