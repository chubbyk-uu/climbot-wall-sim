# 历史分册 2

### 6.1 总体结构

机器人采用扁平、低重心的三轮布局：

- 两个差分主动轮布置在机器人中部略靠前的左右两侧，不放在机体最前沿；
- 一个随动轮布置在后部中央；
- 主动轮分别由独立连续转动关节驱动；
- 随动轮不提供驱动力，第一版采用球形随动轮。

俯视墙面的概念布局：

```text
       机器人前进方向
              ↑
       O─────────────O  ← 主动轮轴
    左主动轮       右主动轮
              │
              ●  吸附合力/质心附近
              │
              o  后球形随动轮
```

### 6.2 模型要求

- 机体厚度尽量小，但惯量必须物理合理；
- 质量、质心、惯量、轮径、轮距和轴距全部参数化；
- 碰撞模型保持简单稳定，不使用不必要的高面数网格；
- 质心和吸附合力位于主动轮轴之后、后球形随动轮之前，并落在三点支撑三角形内部；
- 质心尽量靠近墙面，以减小重力因离墙高度产生的倾覆力矩；
- 吸附合力与主动轮轴之间必须保留明确的稳定力臂，不能为了提高主动轮载荷而与主动轮轴重合；
- 主动轮轴线和 DiffDrive 配置必须与墙面运动平面匹配；
- 后随动轮采用球形随动轮或等效的物理稳定简化模型，避免万向脚轮高频摆振影响轨迹；
- 外观应能直观看出机器人前向、左右主动轮和后随动轮。

### 6.3 吸附稳定性与法向载荷分配

设主动轮轴到后球形随动轮的距离为 `L`，吸附合力位于主动轮轴后方 `d`。忽略其他倾覆力矩时，三点接触的近似法向载荷为：

```text
N_rear  = F_s × d / L
N_drive = F_s × (1 - d / L)
```

其中 `F_s` 为总吸附力，`N_rear` 为后球形随动轮载荷，`N_drive` 为两个主动轮载荷之和。

初始设计建议（**静止工况**）：

- `d = 0.25L～0.35L`；
- 两个主动轮合计承担约 `65%～80%` 的法向载荷；
- 后球形随动轮承担约 `20%～35%` 的法向载荷；
- 左右主动轮法向载荷应基本对称。该项仅在航向沿墙面竖直（重力位于机器人纵向对称面内）时成立；航向水平时重力必然产生滚转力矩 `mgh`，左右载荷差为 `2mgh / 轮距`，此时应以该式核对而非要求对称。

上述比例为初始设计目标，最终数值通过 Gazebo 接触力和运动测试标定。

**运动工况的载荷转移与放宽后的判据。** 机器人离墙质心高度 `h` 会使重力产生倾覆力矩 `M_g = mgh`，上行与下行之间的后轮载荷摆幅为：

```text
ΔN = 2 × m × g × h / L
```

该摆幅与吸附力 `F_s` 无关，而 `20%～35%` 区间的绝对宽度正比于 `F_s`。因此要让**所有姿态**都落在该区间，需要 `2mgh/L ≤ 0.15 F_s`；对本项目的参数（`m = 14.5 kg`、`L = 0.33 m`、`F_s = 220 N`）意味着 `h ≤ 3.8 cm`，对该机器人不现实。

据此，法向载荷判据分为两级：

- **静止工况**：后球形随动轮承担 `20%～35%`，左右主动轮基本对称；
- **运动工况**（直行、上下行、制动、原地转向）：三个接触点法向反力必须全部为正，且**最恶劣工况下后球形随动轮不低于 `0.15 F_s`**。

放宽运动工况判据的依据是 `results/` 中 `measure_normal_loads.py` 的实测数据，而非估算。若后续通过加长 `L`、降低 `h` 或提高 `F_s` 使全姿态都能落回 `20%～35%`，应恢复更严格的判据并更新本节。

## 7. 驱动与底层控制

机器人接收标准二维速度指令：

```text
linear.x  = 墙面平面内的前进速度
angular.z = 绕墙面法向的旋转角速度
```

实际 ROS/Gazebo 轴映射应通过机器人自身坐标系完成，不得让上层算法依赖墙体恰好位于某个世界坐标平面。

底层差分驱动需要支持：

- 线速度、角速度限幅；
- 线加速度、角加速度限幅；
- 左右主动轮编码器或关节状态输出；
- 由轮速计算的连续里程计；
- 原地转向；
- 停车时速度归零。

## 8. 传感器与定位

### 8.1 Gazebo 真值

Gazebo 世界位姿作为评估真值，独立记录，不直接作为控制器的无噪声反馈。

### 8.2 模拟全站仪

模拟全站仪由 Gazebo 真值派生，至少输出机器人在工作坐标系中的绝对位置。模型应支持以下可配置项：

- 发布频率；
- 高斯测量噪声；
- 固定或随机延迟；
- 可选丢帧；
- 消息时间戳和坐标系标识。

本项目真机全站仪的基准发布频率为 **12 Hz**；仿真默认使用相同频率。阶段 C 的初始噪声设为位置一倍标准差 1 mm、固定传输延迟 10 ms，均必须通过 launch/YAML 参数可配置，不得将其写死在控制器中。

阶段 C 的 `odom` 为固定墙面工作坐标系：`+X` 沿初始前进方向，`+Y` 向上，`+Z` 离墙，**原点位于墙面左下角**——整个作业面因此是 `x ∈ [0, 宽]`、`y ∈ [0, 高]`，区域定义、轨迹记录和日志中都不出现负坐标。模拟全站仪适配节点必须把 Gazebo 世界位置转换至该坐标系后再发布；原始 Gazebo 真值保留世界坐标，仅供评估。

第一阶段可以持续可见，不实现遮挡判定。全站仪测量不得与真值轨迹使用同一个“零噪声控制接口”。

### 8.3 IMU

IMU 至少提供：

- 角速度；
- 线加速度；
- 可配置噪声和偏置；
- 正确的安装位姿和坐标变换。

Gazebo IMU 若未在 ROS 消息中正确填充姿态协方差，必须经适配节点发布带噪声及非零姿态协方差的 EKF 输入；不得将零协方差的理想仿真姿态直接融合。第一版姿态噪声基准为一倍标准差 0.5°，后续按真机 IMU 的静态和动态标定数据调整。

IMU 输出的是角速度和线加速度，不将其错误描述为直接输出角加速度。墙面航向估计可融合陀螺仪、重力方向及外部位置约束，但动态加速度对重力观测的污染需要通过融合算法处理。

### 8.4 轮式里程计

- 由主动轮编码器或关节状态推算；
- 连续累计，不在路点或边缘处清零；
- 允许因横向侧滑而与真实位置产生偏差；
- 不得直接使用 Gazebo 真值伪装成轮式里程计。
- 爬壁工况的前向速度与绕墙面法向角速度协方差必须显著大于同编码器的平地初值，并作为可配置参数。其不确定度应覆盖附着力变化、重力诱发微滑、轮墙接触顺从性和吸附力变化；原始编码器里程计与协方差适配后的 EKF 输入必须保留为独立话题。

上述“不得清零”适用于本项目有全站仪绝对定位的主控制链。没有全站仪、只依靠
里程计和边缘检测的简化模式，可以在检测到边缘后重置该扫描行的**局部行程计数**，
但不得重置全局 `odom`、EKF 状态或 TF；该简化模式不属于第一阶段主控制器范围。

### 8.5 状态估计

融合目标是输出机器人在墙面工作坐标系中的连续位姿和速度，输入包括：

- 模拟全站仪绝对位置；
- IMU；
- 轮式里程计。

第一版不从零编写 EKF，优先使用 ROS 2 `robot_localization` 包的 `ekf_node`：

- 使用完整三维状态配置，不启用默认面向地面移动机器人的 `two_d_mode`；
- 所有测量必须具有正确时间戳、协方差和 TF；
- 模拟全站仪只融合其实际提供的绝对位置分量，不伪造航向或速度；
- 轮式里程计主要提供轮子可观测的前向速度和绕墙面法向的角运动，不伪造横向速度观测；
- IMU 根据实际模型融合姿态、角速度和经过验证的线加速度分量；
- Gazebo 真值只用于测试评价，不输入 EKF；
- 通过传感器坐标变换和配置选择，使滤波状态与 `wall` 工作坐标系含义一致；
- 为避免重复使用同一信息，不同时融合由同一轮编码器推导出的高度相关位姿和速度分量，除非验证其协方差处理正确。

当前 EKF 默认以 `50 Hz` 输出融合位姿，控制器也以 `50 Hz` 为第一版运行频率。
全站仪的 `12 Hz` 是绝对位置校正频率；两个全站仪样本之间由 IMU 和轮式里程计
维持高频状态估计。高频 EKF 输出不等价于高频独立绝对测量，控制增益必须结合
测量协方差和延迟设置，不能因输出频率较高而使用过激的横轨位置增益。

`robot_localization` 的配置文件、输入输出话题、状态分量选择、协方差和 TF 发布职责必须纳入版本控制。模拟全站仪若不能直接提供 `ekf_node` 支持的消息类型，应增加适配节点，将其转换为带时间戳、坐标系和协方差的标准 ROS 2 位姿或里程计消息。

采用现成 EKF 的目的，是先验证传感器—定位—规划—控制完整链路，而不是把滤波器设计本身作为第一阶段研究内容。

只有在测试证明 `robot_localization` 无法稳定表达任意壁面方向、墙面运动约束或本项目传感器模型时，才启动专用 EKF 的设计。专用滤波器的候选墙面二维状态为：

```text
x = [u, v, yaw, velocity_u, velocity_v, yaw_rate]ᵀ
```

切换到专用 EKF 前必须保留失败数据，明确现成模块不满足的指标，并更新本文档及接口设计；不得仅因调参尚未完成就重复实现滤波器。

## 9. 工作区域与弓字形覆盖路径生成

### 9.1 输入

第一阶段工作区域为 `odom` 墙面坐标系内的轴对齐矩形或等腰梯形，区域底边默认与墙底边平行。输入至少包括：

- 区域类型：矩形或等腰梯形；
- 矩形的左下角 A、右上角 B；
- 等腰梯形在 A、B 基础上增加右下角 C；
- 扫描方向；
- 检测有效宽度，以及沿行进方向的有效检测长度；
- 相邻扫描带重叠率，或直接指定道间距；
- 机器人轮廓尺寸；
- 边缘安全距离；
- 任务起始角点或自动选择策略。

输入既支持 YAML/ROS 参数，也支持 RViz `Publish Point` 鼠标点选。矩形依次点击 A（左下）、B（右上）；等腰梯形依次点击 A（左下）、B（右上）、C（右下）。鼠标点必须投影到墙面工作平面，规划只使用墙面二维坐标。

矩形的其余两点由 A、B 直接补全。等腰梯形的两个底边点若存在高度偏差，使用平均高度修正：

```text
y_bottom = (A.y + C.y) / 2
A' = (A.x, y_bottom)
C' = (C.x, y_bottom)
center_x = (A.x + C.x) / 2
D = (2 × center_x - B.x, B.y)    左上点
```

由此得到顺序为 A'（左下）、C'（右下）、B（右上）、D（左上）的等腰梯形。必须检查底边宽度、高度、上底宽度、面积和顶点顺序；内缩后区域消失时拒绝规划。上下底宽度在容差内相等时允许视为矩形。

### 9.2 有效区域

规划前应根据机器人外形和安全距离将工作区域向内收缩。内缩采用四条边沿内法向平移后求相邻交点的方法，不得只修改轴对齐包围盒。机器人中心轨迹不得直接落在原始墙面边界上；等腰梯形内缩后仍应保持上下底平行和左右对称。

必须区分两个用途不同的区域：

- `coverage_region`：因接口兼容保留的字段名，现表示用户点选的机器人任务可走区；
- `motion_region`：整面墙按机器人轮廓和安全距离内缩得到的绝对安全运动区。

现场操作员首先约束机器人可以在哪里扫描，避免接近墙边或现场障碍；不要求输入一个
必须逐点完整拍到的规则墙面目标。矩形或等腰梯形 `coverage_region` 必须完整位于
`motion_region` 内，所有蓝色名义 `base_link` 路点必须位于 `coverage_region` 内；从远处
进入首点的关闭采集进场段可位于两者之间，但任何实际或动态参考均不得离开
`motion_region`。

相机预计覆盖区不是输入 Polygon，而是根据每条 `SCAN`、相机外参及二维有效视场得到的
矩形扫掠带并集。因此它可以有阶梯状或不规则边缘，也可以伸出用户任务可走区；规划器
计算并显示它以及“可走区中被预计拍到的比例”。默认只报告比例并尽量覆盖，不因无法把
整个可走区拍满而拒绝一条安全路径；有合同覆盖率门限的部署才显式设置正数
`minimum_nominal_coverage_ratio`。

竖向扫描
底部的转向点到 `motion_region` 下边界必须保留转向下滑余量，第一版使用
`turn_clearance = 0.06 m`；不足时上移转向点或拒绝任务，不得依赖控制器越界补救。

推荐道间距计算方式：

```text
row_spacing = detection_width × (1 - overlap_ratio)
```

若用户直接指定道间距，则仍需验证其不大于允许的最大道间距。
