# 历史分册 4

### 10.7 横向与竖向换道策略

两种扫描方向共用 §10.3～§10.6 的直线控制器和同一套转后入轨判据。扫描线一旦
开始正式跟踪，其起终点必须冻结，不能在执行中不断移动参考线或把直线改成曲线。

**横向为主。** 转向下滑垂直于下一条水平 `SCAN`，不能留给扫描段吸收。第一次
转向稳定后，以 EKF 实际位置作为竖直 `TRANSITION` 起点；该换道段终点在下一
水平扫描线上方预留一次预计转向下滑量，使第二次转向后落入下一扫描线容差。
预计量只作前馈，转向后的 EKF 实际位置用于统一的入轨判定。梯形斜向换道
中接触状态可能使实测下坠大于按转角线性估计值，因此第二次转向预留量取“标定角度
模型”和第一次转向实际下坠量中的较大值；这只更新动态执行参考，不修改名义任务。

**竖向为主。** 不在扫描终点上方预留空间，不逐列倒车，也不要求第二次转向后
返回名义起点。设当前竖直扫描名义终点为 `P`、下一扫描名义起点为 `Q`：

```text
竖直 SCAN 到 P
→ 原地转向并允许下滑到实测 P1
→ 动态生成并跟踪 P1 到 Q 的斜直线 TRANSITION
→ 原地转向并允许下滑到实测 Q1
→ 按统一入轨判据确定下一条平行 SCAN
```

`P1 → Q` 是采集关闭的直线，不要求水平。竖向不做转向下坠预补偿，也不增加返回
`Q` 的倒车动作。向下扫描可能由此少覆盖顶部约一次转向下滑长度；不得用机器人
中心线是否到达 `Q` 直接判断漏扫，而应使用检测装置的二维有效足迹计算实际扫过区域。

第二次转向稳定后，对横向和竖向扫描统一计算机器人相对下一条名义扫描线的法向
偏差。默认处理如下：

- 偏差不大于 `0.045 m`：以当前实测法向坐标平移整条扫描线，冻结一条与名义线
  平行的直线，并从当前沿轨投影处开始正式 `SCAN`；允许小位置偏差，但不允许斜走；
- 偏差在 `0.045～0.12 m`：采集保持关闭，以 `0.08 m/s` 只向前执行一次小弧线，
  将转向与前进混合完成；弧线加入与正式直线控制同源的重力侧滑前馈，偏差收敛到
  `0.03 m` 后重新对齐航向，冻结平行直线并
  开始正式 `SCAN`；不倒车，不增加独立短直线入轨，也不反复重规划弧线；
- 偏差大于 `0.12 m`、小弧线超过 `15 s` 未收敛、即将越过扫描终点或动态终点越出
  `motion_region`：停车并报告失败。

小弧线只是异常偏差下的入轨动作，不属于正式扫描轨迹；正式 `SCAN` 仍必须是直线。
横向与竖向只在下坠前馈上不同：横向保留第二次转向下坠预补偿，竖向不预补偿。

覆盖模型至少包含垂直于行进方向的 `detection_width` 和沿行进方向的
`detection_length`。默认任务只报告预计／实测覆盖率并尽量覆盖，不因可走区未被完整
拍到而改变蓝线路径或拒绝安全任务。只有合同明确给出正数覆盖率门限时，规划／验收才
按该门限处理；此时可显式请求一条采集开启的顶部水平收边直线，不得为每一列增加倒车
修正。收边线及其过渡同样必须位于 `motion_region`。`detection_length` 尚未由真实检测
载荷标定时按保守值处理，不能凭视觉估计宣称已经覆盖。

### 10.8 已实测的扰动量

以下数值来自 `results/` 中的可重复实验，控制器设计必须以它们为输入，而不是重新估算。改变质量、吸附力、质心高度或 WheelSlip 参数后必须重新测量。

**原地转向下滑。** 原地转向时两主动轮反向旋转、轮胎横向刮擦，静摩擦被破坏，机器人沿墙面下滑：

```text
下滑量 ≈ 0.50 mm × |转角(度)|
```

30°～180° 范围内该系数稳定在 `0.48～0.54 mm/度`。**该下滑与转向速度无关**：0.30 rad/s 与 0.60 rad/s 下测得 `0.504` 与 `0.507 mm/度`，位移相差不足 1 mm，尽管耗时相差一倍。因此不能靠提高转向速度减小它。一次 90° 转向下滑约 `45 mm`，已超过 §14.3 规定的 `30 mm` 路点终点容差，弓字形路径每换一道有两次转向。

换道处理必须遵循 §10.7：横向为主时在竖直换道段预留第二次转向下滑量；竖向为主时接受下滑并动态生成斜直线换道，不逐列倒车。第二次转向后按统一入轨判据冻结平行扫描线，仅在偏差较大时执行一次前进小弧线。§10.2 要求正式原地转向期间 `v ≡ 0`；小弧线是转向结束后的独立入轨状态，不属于原地转向。

**仅有航向闭环不足以抑制侧滑。** 四方向实测中，控制器已用融合航向锁定目标航向，水平段仍下沉 `125 mm / 1.200 m`（10.4%）和 `88 mm / 1.116 m`（7.9%）。航向环只约束机器人朝向，不约束其位置；必须按 §10.4 增加横轨位置外环，否则机器人会保持水平朝向被重力横推下去。

**竖直段侧偏很小。** 纯上行、下行的横向偏移仅 `3～5 mm`（行程 1.13～1.22 m），约 0.3%。侧滑补偿的设计目标是水平和斜向段。

### 10.9 参考点必须与旋转中心重合

见 §4.3 的 `base_link` 定义。若跟踪的参考点偏离差分驱动的瞬时旋转中心 `d`，一次转角 `Δθ` 的原地转向会使该点扫过弦长 `2d·sin(Δθ/2)`，这是纯运动学位移，与滑移无关。规划、跟踪、里程计和真值评估必须全部使用同一个参考点。

## 11. 任务状态机

第一阶段至少包含：

```text
IDLE                等待任务
PLAN                生成并验证覆盖路径
GO_TO_START         前往或确认任务起点
ALIGN               原地对准当前线段
TRACK_LINE          跟踪当前直线段
FINAL_APPROACH      低速收敛到当前终点
WAYPOINT_REACHED    停止并切换下一段
MISSION_COMPLETE    完成全部扫描
STOPPED             安全停止
ERROR               故障停车
```

需要处理的异常至少包括：

- 工作区域或参数非法；
- 定位数据超时；
- TF 不可用；
- 控制指令超时；
- 长时间无法到达路点；
- 机器人越出安全区域。

任何影响定位和安全边界判断的严重异常都应使机器人停车。

### 11.1 任务确认与启动

RViz 点选或参数输入只生成任务预览，不得自动驱动机器人。规划器发布最新有效
`CoverageTask` 后，独立任务管理器缓存并显示它的 `task_id + revision`；操作员明确
发出开始命令时，管理器才把该版本作为 Action Goal 发送到 `/coverage/execute`。
Action 接受后冻结完整任务，后续重新点选或重规划只能更新预览，不能热切换正在
执行的任务。开始、取消和故障处理均必须经过同一管理器，取消时先停车再结束 Action。

若 Goal 请求已发出但执行器在返回接受结果前失联，管理器不得仅凭 Action server 不可
发现或当前速度静默就推断该请求不会在之后被接受，默认应保持停车锁定并拒绝新任务。
为避免只能重启管理器，允许提供显式的两阶段人工恢复：操作员二次确认后放弃监督未知
Goal，管理器进入 `RECOVERY_LOCKED` 并持续请求速度保持；操作员确认硬件急停、驱动失能
或执行器确已终止后，才可单独 Rearm。强制放弃本身不得开放 Start，也不得表述为任务
已经停止；实机的最终安全边界仍由默认失效关闭的硬件停机回路承担。

若 Goal 尚未发出、管理器正等待速度保持解除确认，等待同样必须有上限且 Cancel 必须可用。
超时、取消或执行器在解除后消失时，管理器不得直接恢复 READY：解除请求可能已在看门狗中
生效但响应丢失。它应丢弃未发送 Goal、重新请求保持、进入 `RECOVERY_LOCKED`，由操作员
确认停车后 Rearm；该分支不属于“未知 Goal”，不使用 Force abandon。

第一版先提供可由命令行调用的开始/取消服务；服务行为稳定后再增加 RViz 面板中的
“重新规划、开始、取消/停车”按钮、任务版本、执行进度和错误显示。RViz 面板只负责
人机交互，任务锁定、版本检查和安全状态转换不得放在界面插件中。

### 11.2 远距离任务起点进入

完整任务不得假设机器人出生在第一个路点附近。`GO_TO_START`（实现状态名可使用
`APPROACH_START`）按以下顺序执行：

```text
验证当前位姿、首个路点和进入直线位于 motion_region
→ 若第一段是 SCAN 且墙内空间允许，先在扫描线起点后方 `0.40 m` 建立同向进入跑道
→ 原地对准进入目标，采集关闭，沿直线驶向跑道点和首个路点
→ 空间到达并停稳
→ 对准第一条 SCAN
→ 开始正式采集
```

跑道点只用于让远距离接近后的首条扫描也获得稳定直线入轨条件；空间不足时跳过跑道，
由首条扫描使用与转后扫描相同的平行线/小弧线规则处理残余偏差。进入段坚持
“原地转向＋直线运动”，不计入覆盖轨迹，不允许用运行时间代替空间到达
判据。当前位置、首个路点或进入线不安全，定位无效，或者进入过程超时，均应拒绝或
终止任务并停车。至少测试 `0.3 m`、`1 m`、`2 m` 起点距离，来自首点四个方向以及
相同、相反和近似垂直的初始航向；还应覆盖靠近安全边界和不可进入工况。

**速度指令看门狗是强制项，不是可选项。** Gazebo 的 DiffDrive **无限期锁存最后一条速度指令，没有任何内建超时**：实测发布一条 `Twist` 后让发布者退出，机器人仍以恒定速度持续行驶（20 秒内测得 0.131 m/s 匀速）。因此控制器崩溃、被杀或话题中断时，机器人不会停下，而会一路开出墙面边缘并在重力和吸附力作用下自由坠落——本项目已实际发生过一次，机器人飞到距墙面 75 km 处。

要求：

- 系统中必须有一个节点在超过配置时限未收到新速度指令时主动发布零速；超时值可配置；
- 任何会发布 `cmd_vel` 的脚本或节点，都必须在收到 `SIGINT`/`SIGTERM` 时于退出前发布停车指令（Python 的 `finally` 在 `SIGTERM` 下不执行，必须用信号处理器）；
- 使用键盘遥控时需注意：`teleop_twist_keyboard` 仅在按键时发布，看门狗超时值须大于按键自动重复间隔。

## 12. 参数化与可重复性

以下参数不得硬编码在算法中：

- 墙体尺寸和位姿；
- 工作区域；
- 机器人质量、惯量和几何尺寸；
- 轮径、轮距和轴距；
- 吸附力；
- 摩擦和横向/纵向滑移；
- 传感器频率、噪声、延迟和偏置；
- 速度和加速度限制；
- 轨迹间距、检测宽度、检测长度、安全边距和转向安全余量；
- PID 参数和航向修正角限制；
- 各类到达容差、超时和验收阈值。

固定随机种子的测试必须可重复。所有关键实验应保存参数文件、软件版本和结果数据。
正式侧滑标定必须从全新仿真世界开始，防止上一轮的位姿、滤波状态和已行驶距离
污染下一轮；同一次标定内部的三次水平运动应使用融合航向保持，但不得启用横轨
位置纠偏。

## 13. 分阶段实施方案

### 阶段 A：基础物理与机器人模型

1. 建立垂直墙面和标准重力世界；
2. 建立扁平三轮机器人模型；
3. 配置两个前主动轮的差分驱动；
4. 配置后随动轮；
5. 施加恒定法向吸附力；
6. 验证静止吸附、前进、后退、原地转向和停止。

### 阶段 B：运动侧滑模型

1. 配置轮墙摩擦；
2. 配置横向和纵向 WheelSlip；
3. 验证静止时基本不下滑；
4. 禁用轨迹纠偏，测量水平运动时的自然下滑；
5. 标定滑移参数，使现象稳定且可重复。

### 阶段 C：传感器与定位融合

1. 发布轮式里程计；
2. 添加 IMU；
3. 发布带噪声、频率和延迟的模拟全站仪绝对位置；
4. 建立连续 TF；
5. 实现或配置融合定位；
6. 对比轮式里程计、融合位姿和 Gazebo 真值。

### 阶段 D：覆盖路径规划

1. 接收矩形或等腰梯形工作区域和路径参数，支持 YAML 与 RViz 点选；
2. 计算机器人中心的安全有效区域；
3. 自动生成弓字形折线路径；
4. 可视化路点、扫描线、方向和安全边界；
5. 对非法输入给出明确错误。

### 阶段 E：自定义轨迹跟踪

1. 实现任务状态机；
2. 实现原地转向轨迹和航向闭环；
3. 实现直线段空间速度规划与加速度限幅；
4. 实现沿轨、横轨和航向闭环；
5. 实现参考防超前、限幅、抗饱和和终点收敛；
6. 验证重力侧滑下的自动抬头补偿与直线跟踪。
7. 增加任务管理器，将确认后的规划版本发送给覆盖 Action；
8. 实现采集关闭的远距离任务起点进入，并验证不可进入时安全停车。

E3 已完成第 4、5 项的可复用单段核心和参数化节点：它以 EKF `odom` 位姿在
50 Hz 仿真时钟下计算沿轨、横轨与航向误差；水平行驶按已标定的下滑比例生成有限的
抬头前馈，横轨反馈继续收敛残差。航向超出对准阈值时线速度为零，终点按制动距离
减速；输出再经过线/角加速度与左右轮联合速度、加速度限幅。仿真 launch 已把键盘、
实验脚本和该节点统一接到 `/control/cmd_vel`，由速度看门狗唯一输出 Gazebo
`/cmd_vel`；当前一次只允许运行一个上游控制源。

### 阶段 F：系统测试和数据评价

1. 完成单条水平、竖直和斜向直线测试；
2. 分别完成横向为主和竖向为主的完整矩形弓字形覆盖任务；
3. 自动输出轨迹误差和覆盖率；
4. 对比关闭和开启横轨闭环时的下滑差异；
5. 固化启动、测试、绘图和结果导出流程。

## 14. 验收标准
