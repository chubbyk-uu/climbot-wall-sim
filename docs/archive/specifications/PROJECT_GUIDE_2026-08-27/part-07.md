# 历史分册 7

### 18.6 G4 扫描任务原始数据归档

覆盖任务按规划区域完成扫描和位置触发后，必须把照片及其拍摄标签保存到操作员指定的
任务根目录。归档的唯一图像主数据是相机实际交付的、尚未做光照补偿和畸变校正的
`mono8` 畸变原图；使用 PNG 或 TIFF 无损保存，不得用 JPEG，也不得用在线预览补偿图
替换原图。`/inspection/camera/image_compensated` 只用于调试显示，默认关闭且不进入
正式数据集。

每张原图必须与同曝光时间戳的标签原子配对，至少保存任务 ID／版本、扫描段和触发号、
文件 SHA-256、相机 `frame_id`、目标与实际沿轨位置、墙面坐标中的相机位置和航向、完整
位姿协方差、图像尺寸／编码，以及相机内参、畸变参数、机械外参和平场标定的版本或
哈希。任务目录还要保存区域、规划路径、软件提交、开始／结束时间、预期／成功／失败
照片数和失败原因。图片与标签任一写入失败时该触发不得计为成功；先写临时文件，校验
后原子改名，避免掉电留下看似有效的半对数据。

自动位置触发按相机沿冻结 SCAN 参考的进度执行，名义前后重叠为 `20%`。正常触发、图像到达
和 EKF 位姿配对全部异步完成，不能为了逐张拍照限速或停车：扫描线必须按轨迹控制器的巡航
速度平稳直行。归档器以实际标签独立检查相邻间距和目标后滞（默认后滞上限 `25 mm`）；若服务
拒绝、图像超时或 EKF 位姿无法插值，采集器停止当前段的健康 heartbeat，跟踪器在 `0.50 s`
期限内受控中止任务，而不是在机器人已越过目标后静默补拍。

启用巡检的正式 SCAN 把 gate 视作采集器健康 heartbeat：首条 gate 只有一次性的 `2.0 s` 建立
窗口，随后每条 gate 超过 `0.50 s` 未刷新即受控终止任务，绝不将失联解释成正常状态后继续
行驶；进入首条扫描线的 approach、转向和弧线入轨尚未启用采集，不得等待 gate。当前协议只
接受 `active=false` heartbeat，拒绝旧的 `active=true` 位置闸门，避免重新引入逐张拍照减速。
位置触发与曝光位姿均使用完整相机外参，支持非零横向安装偏移。

G4 同时扩展现有 RViz `Coverage Task` 面板，但不能把新控件继续纵向堆在现有正文底部，
也不另建一个挤占渲染区、且可能与任务启动脱节的独立 Inspection 面板。现有 dock 改为
“固定公共状态 + `任务规划`／`巡检采集`／`详情` 三个页签 + 固定安全操作区”：公共区
始终显示任务、状态、段进度和一行采集摘要；Start、Cancel / Stop、Force abandon 和
Rearm 始终位于滚动区外。规划控件和 Replan／Clear points 放在任务页，根目录、采集
开关、预计数量／空间、保存计数、实际任务目录和归档错误放在采集页，管理器／规划器／
最近请求的长文本放在详情页。默认 dock 宽度不因 G4 增大；首版完成后必须在现有 RViz
窗口和多种窄宽度下实测，若显示效果不合适可调整控件排列，但不得隐藏停车入口或采集
故障摘要。

`采集并归档原始图像` 是一个任务级选项：勾选时只在正式 `SCAN` 段位置触发，并强制
把成功曝光归档；不勾选时仍可执行覆盖运动，但不自动拍照，也不创建任务数据集。正式
模式不提供“自动拍照但不保存”。默认值来自 launch／YAML：完整 `coverage_mission` 默认
开启，裸控制节点默认关闭以避免没有相机时意外拒绝纯运动测试；数据根目录默认
`${CLIMBOT_DATA_ROOT}`，可在 RViz 中为本次会话修改，机器相关路径不得写入公共 `.rviz` 文件。
界面选择的是记录器所在计算机上的根目录；RViz 与记录器分机部署时，浏览本机目录不能
代替机器人端或共享挂载路径，界面必须明确显示记录器最终解析出的绝对路径。

按下 Start 后，管理器一次性锁定当前 `task_id + revision`、采集开关、根目录、任务
快照和标定快照。RViz 不直接创建目录或写图，也不能用“先从面板调用记录器、再独立调用
旧 Start”这种存在竞态的两步流程。管理器先要求记录器校验路径、可写性、剩余空间、
`CameraInfo`、外参和必要标定，创建唯一运行目录并写临时 manifest；只有准备成功才向
执行器发 Goal。这个准备过程异步进行，Start 服务只确认请求已受理，解析出的任务目录
和准备失败原因通过任务状态显示；Capture 页的名义总预计数只用于容量预留，已冻结实际
计划数则随每条正式 SCAN 的冻结而单调累加，二者必须分列显示，不能把当前累计误当作任务
总数。任务运行期间采集选项和路径冻结，关闭 RViz 不影响记录器。

根目录下按任务和每次运行分层，例如
`<output_root>/<safe-task-id>/r<revision>_<UTC-time>_<run-id>/`，从而允许同一任务版本
重复执行而不覆盖旧数据。任务成功、取消和故障分别封存为 `completed`、`canceled` 和
`failed`，三者都保留已经原子提交的有效图像。正式采集时若记录器失联、磁盘写入失败
或图像—标签配对失效，默认请求任务受控停车，不能继续生成表面完成但数据不完整的
结果；准备阶段失败则机器人不得开始运动。

### 18.7 离线预处理与墙面拼接

后处理不另建仓库，先在本仓库内以独立包解耦：`climbot_inspection` 只负责采集和原始
归档；`climbot_image_processing` 负责离线暗场／平场、去噪和畸变校正；`climbot_mosaic`
负责其后的输入预检、墙面投影、匹配、全局优化和融合。三个步骤可独立运行，后两
包不得成为规划器、控制器或在线采集的依赖；以后只有出现独立发布或团队维护需求时才
拆成单独仓库。

离线顺序固定为：校验已封存原图和标签；在原始传感器像素坐标中做暗场／平场光照补偿；再按
对应 `K/D` 做畸变校正；利用相机外参、曝光位姿和墙平面模型生成米制初始投影；依据
足迹相交建立候选重叠图；只在有效重叠区域提取和匹配特征并用 RANSAC 剔除外点；最后
进行带先验的鲁棒全局位姿图优化或束调整，再完成接缝选择、融合和不确定度输出。

全局优化不能表述为单纯“让所有照片的位姿方差最小”。正确目标是：以 EKF 拍摄位姿及
其协方差作为绝对先验，以重叠图像匹配作为相对约束，固定至少一个规范自由度，使用
Huber/Cauchy 等鲁棒损失最小化加权先验残差和重投影／配准残差，使局部误差在全图一致
分配。优化后再由信息矩阵估计位姿协方差，并同时报告残差、内点率、连通分量和无法
可靠拼接的区域；不得仅靠缩小协方差数值宣称精度提高。

第一版 `climbot_image_processing` 的离线 CLI 接受一个已完成的 G4 run 和一个不存在的独立
输出目录，先对每张原图 SHA-256、标签和 `CameraInfo` 做完整预检，再以临时目录完成暗场／
平场、可选去噪和去畸变，最后原子发布输出目录。平场 NPZ 与暗场图由用户显式传入；若归档
含平场哈希引用则必须相符。输出保留原标签字段，增加处理后图像 SHA-256，写入零畸变的
`rectified_camera_info.yaml` 与不含本机绝对路径的处理 manifest。原始归档及其文件绝不修改。
预处理可按帧有界多进程并行：去畸变 remap 在主进程只计算一次，worker 使用只读共享上下文，
每个 worker 的 OpenCV 内部线程固定为一；实际 worker 数受 `--jobs` 和
`--memory-budget-gb` 共同限制，并写入 processing manifest。不同并发数必须保持帧顺序、
哈希和处理语义一致。

`climbot_mosaic` 的第一道门禁只接受已完成的 processed-run，逐张复核处理图 SHA-256、标签、
去畸变相机模型、固定安装外参和曝光位姿／协方差；跨 run 的相机模型或全局帧键不一致时必须
在投影前失败。它只输出不含本机绝对路径的严格 JSON 预检摘要，且绝不读取 ROS 图或 Gazebo
真值。后续墙面投影、特征匹配和融合只能使用该预检产生的内存对象，不能重新以宽松规则解析
归档目录。

最终拼接结果必须同时保留“只用曝光 EKF 位姿”和“视觉约束全局优化后位姿”两套无损墙面
母版。二者使用相同照片、墙面范围、米制分辨率、灰度与融合权重，唯一允许变化的是照片位姿；
同时输出并排预览、差分图和同口径质量指标，以判断优化是否真正减少接缝、重影和局部错位。

当前曝光位姿采用平面墙 `x/y/yaw + 固定相机墙距`：相机 `z` 直接取冻结安装外参，不叠加
Gazebo canonical link 在墙法向的坐标。后者代表仿真刚体参考点而不是第二段相机支架；重复
相加会把本应约 `0.275 m` 的墙距记成约 `0.327 m`，导致初始投影尺度系统性放大。完整 SE(3)
墙面起伏模型只能作为后续显式接口升级，不能改变当前二维标签的含义。

拼接验收必须同时保留弱纹理混凝土基线和独立诊断墙。诊断墙可增加少量非周期施工接缝、
斜裂纹、不同修补块与离散标记，便于在原分辨率观察接缝和已知变换；不得用密集周期网格把
真实匹配问题变成过度简单的标定靶。新增结构必须有确定的米制几何、生成种子、贴图哈希和
独立启动配置，不能静默替换正常仿真墙。

定位仿真采用双 profile：`precision` 保持现有高精度全站仪基线；`realistic` 第一版只引入两项
可解释误差：棱镜到机器人参考点的**未建模外参残差**，以及全站仪**测量时间戳偏差／小抖动**。
前者以机器人坐标系中的固定残差经真值航向旋转后投影到墙面，因而自然产生往返扫描的航向相关
位置差；后者只篡改观测时间戳，不改变已知的 `10 ms` 传输延迟。两者均不得以放大全站仪白噪声
或只增大协方差替代：协方差改变 EKF 权重，不会制造真实位姿误差。低频相关漂移、短时丢测和
载荷相关形变保留为后续独立的故障／敏感性 profile，不属于本轮 `realistic` 默认项。

`realistic` 数据的初始调试目标为曝光 EKF 相机位置误差 P95 `20～30 mm`、短时最坏约
`30～50 mm`，最终门限必须由动态实测决定；控制器和归档标签均使用该 EKF 输出，真值只进入
独立验收器。每个误差源必须有开关、单位、种子和真值记录；`precision` 与 `realistic` 的配置、
任务 ID、原图和处理结果必须分开保存，不得覆盖既有基线。
