# 历史分册 1

# 爬壁机器人仿真项目总指导规范

## 1. 文档目的

本文档是本项目的总指导规范，用于统一后续仿真环境、机器人模型、传感器、定位融合、全覆盖路径规划、轨迹跟踪控制、测试与验收的目标和实现边界。

后续设计和实现原则上应遵循本文档。若实际开发中需要改变关键目标、系统边界或验收标准，应先更新本文档，再修改代码和配置。

文档职责划分如下：

- `README.md`：项目入口、构建和快速启动；
- `docs/ARCHITECTURE.md`：当前包结构、依赖方向和配置归属；
- `docs/INTERFACES.md`：已实现的 ROS 2 接口、参数和 TF；
- `docs/STATUS.md`：阶段状态、review 闭环和未决事项；
- `results/README.md`：实验结果的用途、有效性和再生成方法。

上述文档描述当前实现，不得修改或降低本规范定义的目标和验收标准；发生冲突时以本规范为准。

## 2. 项目目标

在 Gazebo Sim 中建立一个受真实重力作用的垂直壁面爬壁机器人仿真系统，使机器人能够：

1. 通过持续法向吸附力保持在垂直墙面上；
2. 使用前部两个独立主动轮实现差分驱动，后部使用一个随动轮支撑；
3. 在运动过程中表现出重力导致的横向侧滑，尤其是机器人按水平方向行驶时产生向下漂移；
4. 使用轮式里程计、IMU 和模拟全站仪绝对位置进行位姿估计；
5. 根据用户在壁面上设定的矩形或等腰梯形工作区域，自动生成弓字形全覆盖扫描轨迹；
6. 使用自定义轨迹规划和跟踪算法完成扫描，不依赖 Nav2；
7. 通过位置与航向闭环自动产生向上的航向补偿，使机器人本体可以略微向上偏转，而实际运动轨迹尽量保持为直线；
8. 完成全部扫描后停止，后续可扩展为返回任务起点。

本项目重点验证垂直壁面上的运动、侧滑、定位融合、覆盖路径生成和直线轨迹跟踪，不研究磁吸或负压吸附装置内部机理，也不研究吸附失效过程。

## 3. 已确认的项目边界

### 3.1 本项目包含

- 垂直平面墙体和矩形/等腰梯形任务区域；
- 标准世界重力；
- 恒定、持续、指向墙面的法向吸附力；
- 轮墙接触、摩擦及运动时的轮胎横向滑移；
- 差分驱动机器人动力学；
- IMU、轮式里程计、模拟全站仪和 Gazebo 真值；
- 多传感器位姿融合；
- 矩形区域的弓字形覆盖路径生成；
- 原地转向和分段直线轨迹跟踪；
- 路径、融合轨迹和真值轨迹记录与误差评价；
- RViz 和 Gazebo 中的状态与轨迹可视化。

### 3.2 第一阶段不包含

- Nav2；
- SLAM 和未知环境建图；
- 动态避障和复杂障碍物绕行；
- 磁场、负压腔体、密封泄漏或吸力随距离变化的高保真模型；
- 吸附开启、关闭、脱附和坠落控制逻辑；
- 曲面墙体以及墙面之间的跨面运动；
- 为提高速度而进行的圆弧转弯或路径拐角平滑。

### 3.3 软件平台与编程语言

项目以 ROS 2 为主体，由 ROS 2 负责节点通信、参数、启动、TF、数据记录和可视化；Gazebo Sim 负责物理、传感器和真值仿真，二者通过 `ros_gz_bridge` 或专用接口连接。

编程语言分工如下：

- **C++ / `rclcpp`**：弓字形覆盖路径生成、轨迹跟踪控制、任务状态机、仿真传感器接口，以及必要的 Gazebo System 插件；
- **Python / `rclpy`**：实验管理、辅助工具和非关键在线节点；
- **Python**：离线数据分析、参数扫描、轨迹绘图和验收报告生成；
- **URDF/Xacro/SDF**：机器人与仿真环境建模；
- **YAML**：机器人、物理、传感器、定位融合、控制和验收参数；
- **ROS 2 Python launch**：完整系统的启动与编排。

核心规划、控制和任务状态机默认使用 C++ 实现。Python 不进入对确定性和运行频率要求较高的关键底层控制闭环，除非测试证明其性能满足要求并在本文档中记录例外。

### 3.4 ROS 2 包结构与依赖边界

当前工作区采用以下包结构：

```text
                 climbot_bringup   组合 launch，只有编排
        ┌────────────────┼────────────────┐
        ↓                ↓                ↓
climbot_coverage   climbot_control   climbot_gazebo
        │                │                │
        ├──> climbot_interfaces <──┤       │
        └──> climbot_description <─┴───────┘
```

`climbot_interfaces` 只定义 ROS 接口，不依赖描述、规划、控制或仿真包。依赖必须
从下游指向公共接口和 `climbot_description`，不得反向依赖。规划器和控制器不得
依赖 `climbot_gazebo`，不得读取 Gazebo 真值、WheelSlip、吸附施力或出生位姿。

配置归属必须遵循：

- 机器人几何、质量、轮系、驱动限幅和规划轮廓属于 `climbot_description`；
- 墙面工作坐标系、可作业宽高属于 `climbot_description`；
- 摩擦、WheelSlip、吸附力、出生位姿和仿真传感器属于 `climbot_gazebo`；
- 覆盖区域和扫描参数属于 `climbot_coverage`；
- 轨迹跟踪、状态机、安全超时和控制增益属于 `climbot_control`。

组合 launch 属于 `climbot_bringup`：它只有启动编排，没有节点、算法和参数文件，
可以点名任意下游包，而任何包都不得依赖它。各包的单包 launch 入口留在各自包内。
`ekf_wall.yaml` 是定位链路配置而非编排文件，与喂给它的仿真传感器一同留在
`climbot_gazebo`。

## 4. 坐标系约定

### 4.1 世界坐标系

Gazebo 世界保持标准三维坐标系和真实重力：

```text
gravity = (0, 0, -9.81) m/s²
```

不得通过关闭重力或旋转世界重力来伪造墙面运动。

### 4.2 壁面工作坐标系 `wall`

在墙面上建立右手坐标系：

- 原点：**墙面左下角**。整个作业面因此是 `u ∈ [0, 宽]`、`v ∈ [0, 高]`，区域定义、
  轨迹记录和日志中都不出现负坐标；
- `u`：墙面水平方向，正方向向右；
- `v`：墙面竖直方向，正方向向上；
- `n`：墙面法向；
- 工作区域、覆盖路径和轨迹误差均在 `(u, v)` 平面内表达；
- `wall` 与世界坐标系之间使用固定变换描述。该变换的平移量就是上述原点在世界坐标系
  中的位置，是一个可测量的实机量，不得由仿真里墙体摆放的方式反过来决定。

机器人二维航向角定义在墙面平面内：

- 航向为 `0` 时沿 `+u`；
- 航向正方向按 `wall` 坐标系右手规则确定；
- 所有角度误差必须归一化到 `[-π, π]`。

### 4.3 ROS 坐标关系

建议使用以下 TF 关系：

```text
world / map
└── wall
    └── odom
        └── base_link
            ├── imu_link
            ├── left_wheel_link
            ├── right_wheel_link
            └── caster_link
```

具体发布者可根据定位融合方案调整，但必须满足：

- TF 树唯一、连续、无环；
- `odom` 不得在每段路径开始时重置；
- 分段相对位移通过记录该段起始位姿计算，而不是改变全局坐标系。

**`base_link` 的原点定义为两个主动轮轴的中点在轮墙接触平面上的投影。** 差分驱动的瞬时旋转中心就是该点，因此：

- 原地转向在运动学上不移动 `base_link`，路点仍然是路点；
- 由轮速推算的里程计天然就是该点的位姿，其 `frame_id` 名副其实；
- §10.3 的沿轨、横轨误差和 §10.2 的原地转向都在该点上定义。

不得把 `base_link` 放在机体几何中心或质心。若参考点与旋转中心相距 `d`，一次转角为 `Δθ` 的原地转向会使参考点扫过弦长 `2d·sin(Δθ/2)`；实测 `d = 80 mm` 时一次 90° 转向即产生 113 mm 的纯运动学位移，远超 §14.3 规定的 30 mm 路点终点容差。机体、随动轮和传感器均以相对 `base_link` 的偏置表达。

## 5. 仿真环境

### 5.1 墙体

- 墙体为静态刚体；
- 第一阶段使用平整的垂直矩形墙面；
- 墙面尺寸应明显大于默认工作区域，并为机器人边缘安全距离留出余量；
- 墙面必须具有正确的碰撞几何、法向和摩擦参数；
- 视觉模型与碰撞模型应保持一致，复杂纹理不得影响物理接触。

Gazebo 场景另有一块静态水平地面碰撞平面，其顶面位于墙面工作系 `v=0` 以下
`20 mm`，摩擦系数为 `mu=mu2=0.8`。它只用于提供操作员可见的环境和拦截异常坠落，
正常作业区、轮墙接触及其已标定的侧滑参数均不得接触或依赖该平面。

后续允许为 Gazebo 墙面增加可配置的照片或 PBR 贴图，用于模拟混凝土、金属板、
焊缝、锈蚀和表面缺陷。墙面 `collision` 在第一阶段仍保持已标定的平整几何，贴图、
法线图和粗糙度只作用于 `visual`，不得隐式改变摩擦、WheelSlip 或接触法向力。
若以后需要模拟不同材质区域的真实滑移差异，应单独建立碰撞分区或滑移参数地图，
不得把视觉纹理误当作物理材质模型。

高分辨率墙面因 GPU 单纹理尺寸限制必须分块时，分块只允许发生在存储和 visual 层：
整墙图像坐标必须连续，每块应携带足够的真实邻域像素供纹理过滤和 mipmap 使用，禁止
用边缘复制或彼此无关的小图直接拼接。名义块负责无重叠、无空洞的坐标覆盖；带邻域的
visual 可以外观重叠，但重叠区域必须表示完全相同的墙面坐标和源像素。

### 5.2 吸附力

- 吸附力作为持续外力施加到机器人机体；
- 方向始终沿墙面法向并指向墙内；
- 保留机器人和所有动态部件的重力；
- 吸附力大小作为可配置参数；
- 初始吸附力应足以保证机器人静止时不下滑、不脱离墙面；
- 第一阶段不根据接触距离、速度或姿态动态改变吸附力。

吸附力可以使用 Gazebo 的持续 wrench 实现。若现成系统无法满足受力点和坐标变换要求，再实现简单的自定义 System 插件，但插件仍只负责恒定法向力。

**实现约束：`ApplyLinkWrench` 把力施加在 link 的【原点】，不是质心。** 因此吸附力的作用位置由承力 link 的 `<pose>` 决定，与 `<inertial><pose>` 无关。当二者恰好重合时这个区别不可见，一旦分离就会静默改变载荷分配——实测把承力 link 原点移到主动轮轴后，后随动轮法向载荷由 `73.33 N` 降至 `0.00 N`，全部转移到两个主动轮。修改机器人坐标系时必须单独验证吸附作用点未被移动，验证方法是重跑法向载荷测试并逐项比对。

吸附力不得只考虑大小，还必须考虑作用位置及其产生的法向载荷分配：

- 吸附合力在墙面上的投影必须位于两个主动轮与后随动轮构成的三角支撑区域内部；
- 吸附合力不得与主动轮轴重合，否则后随动轮法向载荷可能接近零，机器人处于容易翘起的临界状态；
- 若真实机器人有多个磁铁或吸盘，仿真可将恒定总吸附力分配到多个固定作用点；这仍属于第一阶段的恒定法向吸附模型；
- 单点或多点实现都必须保持总吸附力和合力作用位置可配置；
- 不得通过固定关节补偿不合理的吸附力位置。

### 5.3 摩擦与侧滑

静止机器人应由静摩擦保持在墙面上，不能靠关闭重力或固定关节实现。

机器人运动时使用 Gazebo WheelSlip 或等效的各向异性滑移模型：

- 纵向滑移较小，保证主动轮具有有效驱动力；
- 横向滑移非零，使重力能够在运动过程中产生沿墙面向下的侧滑；
- 机器人静止时应基本保持高度；
- 机器人水平运动时，在未启用轨迹纠偏的情况下应出现可测量的向下漂移；
- 滑移参数、轮胎摩擦系数和轮载估计均应参数化。

不得仅通过把摩擦系数调到静摩擦临界值来制造下滑，因为这会导致静止状态不稳定，不能准确表达“静止吸附稳定、运动时发生横向蠕滑”的目标现象。

## 6. 机器人模型
