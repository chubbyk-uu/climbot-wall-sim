# 历史分册 5

### 14.1 功能验收

以下项目全部满足，才视为第一阶段功能完成：

- 一条命令或一个 launch 文件能够启动完整仿真；
- 墙面、机器人、重力、吸附力和轮墙接触同时生效；
- 机器人使用两个中部略靠前的主动轮差分驱动，后球形随动轮不主动驱动；
- 吸附合力投影位于三点支撑区域内部，且不与主动轮轴重合；
- 静止、直行、制动和原地转向时，三个轮墙接触点均保持正法向载荷，不发生后轮卸载或机体翘起；最恶劣工况下后球形随动轮法向载荷不低于 `0.15 F_s`（见 §6.3）；
- 机器人能够前进、后退、停止和原地旋转；
- 静止状态下机器人不会持续明显下滑或脱离墙面；
- 关闭横轨纠偏后，水平运动能够观察并测量到向下侧滑；
- 开启横轨纠偏后，控制器能够形成向上的航向补偿并显著减小高度漂移；
- 能够发布 Gazebo 真值、IMU、轮式里程计、模拟全站仪和融合位姿；
- 能够根据任意合法矩形或约定的等腰梯形机器人任务可走区生成横向、纵向弓字形路径；
- 能够按“原地转向＋直线运动”的方式执行完整覆盖任务；
- 任务执行中不重置全局里程计；
- 定位丢失或严重故障时机器人能够停车；
- 完成任务后机器人停止，并输出任务结果。

### 14.2 路径几何验收

- 所有名义路径点均位于用户任务可走区，所有动态执行参考均位于绝对安全 `motion_region` 内；
- 扫描线与指定扫描方向一致且互相平行；
- 相邻扫描线间距满足配置误差要求；
- 相邻扫描方向交替；
- 不生成圆弧拐角或跨路点捷径；
- 蓝色路径不越出指定可走区；黄色相机覆盖按真实外参和足迹推导并报告，不强制为规则 Polygon；
- 动态斜向 `TRANSITION` 和顶部收边扫描仍由直线段组成；
- 同一输入参数应生成完全一致的路径。

### 14.3 轨迹跟踪验收

每条直线段均需基于 Gazebo 真值计算：

- 横轨误差 RMS；
- 最大绝对横轨误差；
- 终点位置误差；
- 转向结束航向误差；
- 实际轨迹长度与规划长度之比；
- 水平段高度漂移；
- 最大航向补偿角和角速度；
- 是否出现切角或明显蛇形振荡。

蛇形评价忽略厘米级以内的小误差过零，重点检查可见横轨往复是否持续并伴随航向
反向摆动；不得把正常噪声附近的过零直接计为控制失败。

第一版建议使用以下默认验收阈值，待机器人实际尺寸和真实数据确定后再冻结最终数值：

| 指标 | 建议初始阈值 |
| --- | ---: |
| 单段横轨误差 RMS | ≤ 20 mm |
| 单段最大绝对横轨误差 | ≤ 50 mm |
| 路点终点位置误差 | ≤ 30 mm |
| 原地转向结束航向误差 | ≤ 2° |
| 完整水平扫描段净高度误差 | ≤ 30 mm |
| 相邻扫描线间距误差 | ≤ 20 mm |
| 任务期间实际拍摄覆盖率 | 默认记录和报告；合同任务可单独冻结下限 |
| 定位严重超时后的停车响应 | ≤ 0.5 s |

上述阈值属于“建议初值”，不是不可修改的物理要求。最终阈值应依据机器人尺寸、检测载荷有效宽度、全站仪精度和期望作业质量确定。

覆盖率必须按机器人实际执行轨迹扫过的二维检测足迹计算，足迹同时使用
`detection_width` 和 `detection_length`。竖向为主的任务不得通过逐列倒车回到名义
扫描起点。若某项合同检查要求补齐顶部，操作员可显式请求一条顶部水平收边扫描；默认
任务不因报告出的覆盖率而强制追加。

`overlap_ratio` 决定相邻扫描带的重叠量，而重叠量同时是相邻扫描线间距误差的吸收
裕度。实测最大间距误差为 `18.4 mm`，当前 `0.20` 的重叠率给出 `100 mm` 重叠；不得
以默认覆盖率只报告为由压缩 `overlap_ratio`，除非重新核算间距误差并确认重叠量仍大于它。

### 14.4 侧滑补偿专项验收

在相同初始状态、速度、吸附力和滑移参数下分别执行：

1. 横轨补偿关闭的水平直线运动；
2. 横轨补偿开启的水平直线运动。

要求：

- 补偿关闭时存在稳定、可重复的向下漂移；
- 补偿关闭时三次水平下降/前进比的总体变异系数不大于 5%；
- 补偿开启后，水平段净高度误差相对关闭状态至少降低 70%；
- 补偿开启后机器人允许保持小幅向上航向偏角；
- 补偿过程不能产生明显蛇形振荡；
- 实际位置轨迹应比机器人机体朝向更接近规划水平直线。

### 14.5 定位验收

- 所有传感器消息时间戳有效；
- TF 树连续且无环；
- 融合定位在正常传感器条件下不中断、不跳变；
- 轮式里程计能体现侧滑造成的不可观测误差；
- 模拟全站仪包含配置的频率、噪声和延迟；
- 融合位置误差应显著小于仅使用轮式里程计时的长期误差；
- 评估脚本不得把控制器使用的估计值当作 Gazebo 真值。
- 第一版应能使用 `robot_localization/ekf_node` 完成全站仪、IMU 和轮式里程计融合；
- `robot_localization` 的输入状态选择、协方差、频率和 TF 发布配置必须可追溯；
- 若改用专用 EKF，必须提供与 `robot_localization` 在同一数据集上的定量对比，并证明现成模块未达到已定义指标。

### 14.6 工程质量验收

- 构建无错误；
- 自动化测试通过；
- 启动和停止过程无残留关键进程；
- 参数集中配置并有单位说明；
- 关键节点、话题、服务、动作和 TF 有文档；
- 至少提供一个默认矩形区域的可复现实验；
- 测试结果包含参数、规划路径、融合轨迹、真值轨迹和指标摘要；
- 不使用硬编码绝对路径依赖特定开发机。
- 核心规划、轨迹控制和任务状态机使用 C++，辅助测试与分析工具可使用 Python；
- ROS 2 包依赖、Gazebo 版本、消息接口和启动入口有明确文档。

## 15. 测试场景

至少建立以下测试：

1. **静止吸附测试**：机器人静止在墙面，验证高度和法向距离稳定；
2. **法向载荷测试**：记录三个轮墙接触点的法向力，验证吸附合力位置、主动轮载荷比例和防翘裕量；
3. **水平自然侧滑测试**：禁用横轨补偿，执行水平直线；
4. **水平补偿测试**：启用横轨补偿，重复相同水平直线；
5. **竖直运动测试**：分别向上和向下运动，验证驱动和定位；
6. **原地转向测试**：测试多个角度，包括小角度三角形速度轨迹和大角度梯形速度轨迹；
7. **单段直线测试**：测试水平、竖直和斜向线段；
8. **矩形覆盖测试**：分别完成横向为主和竖向为主的完整弓字形路径，验证竖向斜线换道、转后平行扫描线、较大偏差时的单次前进小弧线、无逐列倒车和可选顶部收边扫描；
9. **定位噪声测试**：改变全站仪噪声和频率；
10. **定位超时测试**：暂停绝对位置输入，验证安全停车或降级策略；
11. **参数重复性测试**：固定随机种子重复运行，验证结果一致性。

阶段 C 必须提供可重复的滑移标定脚本：使用 Gazebo 真值只作评估，记录静止高度变化、无横轨纠偏且融合航向保持时的水平下降/前进比，以及融合航向保持条件下等时上行、下行速度。每项运动测试至少重复三次，输出均值和水平下降比总体变异系数；标定脚本的速度必须按仿真时间计算，并拒绝超过配置重复性阈值的实验。

## 17. 开发原则

- 先完成简单、稳定、可测量的基础模型，再提高物理和传感器复杂度；
- 机器人不得通过固定关节连接墙面；
- 不关闭重力；
- 不用 Gazebo 真值替代轮式里程计或无噪声全站仪参与正常控制；
- 规划、控制和评价使用统一的墙面工作坐标系；
- 保持模块职责单一，规划器不直接控制车轮，控制器不负责生成工作区域；
- 所有关键参数可配置；
- 每完成一个阶段均应先测试，再进入下一阶段；
- 任何声称完成的功能都必须有可重复的测试或数据支持。

## 18. 后续可扩展方向

完成本规范的第一阶段后，可按需要扩展：

- 梯形和任意凸多边形工作区域；
- 墙面障碍物与局部绕行；
- 全站仪遮挡、丢锁与重定位；
- 自适应侧滑估计和航向前馈；
- 不同墙面材质对应的滑移参数地图；
- Gazebo 墙面照片/PBR 贴图和可配置视觉材质；
- 面阵相机检测覆盖模型、位置触发拍照和图像姿态校正；
- 任务中断、恢复与返回起点；
- 曲面结构和跨墙面运动；
- Nav2 或更通用的任务规划框架。

这些扩展不得妨碍第一阶段“垂直墙面、真实重力、持续吸附、运动侧滑、矩形/等腰梯形弓字覆盖和直线段闭环跟踪”的核心目标。

面阵相机扩展应使用独立的 `climbot_inspection` 包，不把拍照业务塞入规划器或轨迹
控制器。触发点按相机在行进方向的有效视场和重叠率计算：

```text
capture_spacing = longitudinal_field_of_view × (1 - image_overlap_ratio)
```

只允许在正式 `SCAN` 段采集；`GO_TO_START`、`ALIGN`、`TRANSITION` 和小弧线入轨时
关闭采集。触发判断使用 EKF 位姿和当前冻结的动态执行参考，按单调沿轨进度及唯一
触发编号防止定位噪声造成重复拍照，Gazebo 真值只用于评价。每张图像应关联图像
时间戳、任务及版本、扫描线与触发点编号，以及由缓存插值得到的融合位姿。第一版可
采用连续运动位置触发并限制拍照速度；对运动模糊敏感时再增加停车稳定后拍照模式。
