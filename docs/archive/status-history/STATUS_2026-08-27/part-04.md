### 是什么

裸墙上把「起始朝向 × 转角 × 转向方向」扫成网格（`results/turn_band.csv`、
`turn_map.csv`），结论是一条与转角无关的规则：

> 机器人**起步**做原地转向时，若当前朝向偏离竖直 12°~40°，且转向方向会让车头
> 继续下压，则起步瞬间沿车身轴滑掉约 **68 mm**，与转过多少度无关。

三条决定性性质：

1. **与转角无关**——扣掉正常的 0.5 mm/度 后，30°/45°/60°/77°/90° 的额外滑移都是
   68 mm ± 4，是一次性事件；
2. **只在一个方向**——同一朝向反向转完全正常（30° 转向 15.67 mm 对 76.50 mm）；
3. **只怕从带内起步，不怕扫过带**——扫描线末端从 6° 扫过 114°，速率 0.480，正常。

四个危险区（114°、66°、246°、294°，即竖直两侧各约 24°）完全对称，无例外。

链条因此是：斜边 58° → 换道段航向 122° → 重力前馈 −7.6° → 机器人在换道段顶端保持
**114.4°**，正落在带的峰值；旧几何斜边 76° → 换道段 103.6° → 保持 100.3°，在带的
边缘（0.59 mm/度），所以一直没暴露。残留 43 mm 又恰好低于弧线入轨的 45 mm 触发
阈值，纠偏不启动，直接冻结成 43 mm 的间距误差。

### 一度采用过的修法：转出带外（已撤销）

第一版修法是 `turnLeadOut()`：转向前若起始朝向落在带内且方向为车头下压，先朝抬头
方向转出带外，再执行原转向。它确实有效（梯形横向 43.09 → 1.52 mm），但它**绕开
症状而没有消除病因**：每次都要多转十几度，还把一组只在 220 N 下成立的带边界常数
写进了控制器。

查清成因、把吸附力提到 400 N 之后带本身不存在了，这套机制连同它的 4 个单测已整体
撤销，`coverage_execution.{hpp,cpp}`、`line_tracker_node.cpp` 和 `test_line_tracker.cpp`
逐字节回到引入它之前的状态。

### 成因：主动轮摩擦饱和（2026-08-18 补测）

第一版结论写的是"微观成因未查清，剩下是 Gazebo 接触求解器层面的行为"。**那句是错
的**。把吸附力和摩擦系数当自变量扫一遍（`results/band_variants/`，每个变体在
`100/105/110/114/120/125°` 起转 `+30°`），成因很清楚：

| 变体 | 峰值 mm/度 | 判定 |
| --- | ---: | --- |
| 基线（吸附 220 N，`wheel_mu` 1.1） | **2.536** | 带存在 |
| `slip_lateral` 0.12 → 0 | 2.637 | 无关 |
| `slip_longitudinal` 0.04 → 0 | 2.530 | 无关 |
| `caster_mu` 0.35 → 1.1 | 2.536 | 无关 |
| `wheel_mu` 1.1 → 2.2 | **0.416** | 带消失 |
| 吸附 220 → 440 N | **0.416** | 带消失 |

**μ 加倍与 N 加倍给出逐点相同的曲线**（`0.380 / 0.386 / 0.395 / 0.400 / 0.410 /
0.416` 对 `0.380 / 0.386 / 0.394 / 0.400 / 0.409 / 0.416`），支配量是乘积 `μN`。
这是主动轮的**库仑摩擦饱和**，不是求解器伪影。

万向轮的 μ 无关，因为它是滚动的球，给不出可用切向阻力；它承担的载荷等于从主动轮
**白拿走**，只减不加。

### 220 N 贴在脱落悬崖边

沿吸附力细扫：

| 吸附力 | 峰值 mm/度 | 结果 |
| ---: | ---: | --- |
| 210 N | — | **第一次转向即整机脱落**（滑 9.6 m 后自由落体） |
| 215 N | — | 撑过两次转向，第三次在 108.7° 脱落 |
| **220 N（当前配置）** | **2.536** | 不脱落，但带在峰值 |
| 222 N | 1.270 | 带减半 |
| 225 N | 0.531 | **带消失** |
| 230 N | 0.525 | 平 |
| 260 N | 0.508 | 平 |
| 440 N | 0.416 | 平 |

`wheel_mu` 降到 0.7（吸附 220 N）同样直接脱落，静止都撑不住。

静态核算与实测一致：实测轮压 `45.8 + 100.9 = 146.7 N`，主动轮摩擦上限
`1.1 × 146.7 = 161 N`，整机自重 `14.5 kg × 9.807 = 142 N`，**静态安全系数只有
1.13**。原地转向时载荷向万向轮转移，轮压瞬时掉到 `40.3 + 40.4 = 80.7 N`，上限
`89 N` 已低于自重；转移量取决于重力在车身系里的方向，也就是航向——这就是带的来源。
按 `μ × 0.667 F ≥ mg` 反解，静止不打滑要求 `F ≥ 194 N`，与实测 210~215 N 的脱落
门槛吻合。

### 采用的修法：吸附力 220 → 400 N

带是主动轮摩擦饱和，那就把摩擦上限抬起来，而不是躲开它。

| 参数 | 旧值 | 新值 | 依据 |
| --- | ---: | ---: | --- |
| `suction.force_n` | 220.0 | **400.0** | 静态安全系数 `F / 194`：1.13 → **2.06** |
| `nominal_normal_force_n` | 77.0 | **133.3** | 77 是 220 N 时代按"估计 70%"算的；实测占比 66.7%，`400 × 0.667 / 2` |
| `slip_lateral` | 0.12 | **0.208** | 同一条轮胎改按 133.3 N 表述，`× 133.3/77` |
| `slip_longitudinal` | 0.04 | **0.069** | 同上 |
| `turn_slip_per_degree_m` | 0.0005 | **0.00041** | 20 次转向重新拟合，残差 RMS **0.5 mm**（原 2.0 mm） |
| `gravity_slip_ratio` | 0.1056 | **0.1042** | 三次水平段实测 10.42%，`horizontal_cv` 0.53% |

`max_gravity_feedforward_deg` 保持 8.0：侧滑比只动了 1.3%，对应前馈约 5.95°，不触顶。

**柔度与标称载荷必须成对改。** WheelSlip 只用 `compliance / nominal` 这个比值，只改
`nominal` 而不改柔度等于把轮胎调硬 42%，实测后果是全圆散布从 11.6% 炸到 **49.2%**、
转角残差从 0.5 跳到 2.6 mm——单常数的 `turn_slip_per_degree_m` 模型直接失效。两个
一起按 1.7312 倍缩放后，48 个航向与不缩放时**逐点相差 ≤ 0.001 mm/度**，证明这个
比值在 gz-sim 里是严格线性的，改后的配置与原轮胎是同一个被控对象，只是参考载荷
换成了轮子真正承受的那个。

| 配置 | 全圆最小 | 最大 | 散布 | 转角残差 |
| --- | ---: | ---: | ---: | ---: |
| 220 N（旧） | 0.388 | **2.154** | 275% | 2.0 mm |
| 400 N，只改 nominal | 0.225 | 0.394 | 49.2% | 2.6 mm |
| **400 N，柔度同步缩放（采用）** | 0.392 | 0.441 | **11.8%** | **0.5 mm** |

400 N 下六个原危险航向读数 0.392~0.429，与其余航向无异；全圆 48 次转向再无任何峰。

### 遗留

- 挂载相机后自重上升，安全系数按 `1.1 × 0.667 × F / (m·g)` 重算：+2 kg 时降到 1.81。
  再加电池或清洗机构时必须重新核这个数，并重扫一遍全圆确认带没回来。
- 万向轮是滚动球，抢走的法向载荷换不回切向力。`caster_x = -0.33` 力臂很大，前移或
  改成有摩擦的支撑可以在不加吸附力的前提下提高主动轮轮压，尚未评估。

## 2026-08-18 转向结束航向误差：判据与阈值取了同一个数

八个覆盖工况的 `maximum_turn_end_heading_error_deg` 长期落在 `1.68°~2.03°`，阈值
`2.0°`，同一构建可能一次通过一次失败。把吸附力从 220 N 提到 400 N **对这一项毫无
改善**，说明与摩擦余量无关。

### 成因

`line_tracker_node.cpp` 的 `ALIGN_SETTLE`：

```cpp
if (std::abs(line_command.heading_error) <= alignment_tolerance_) {
  command.angular = 0.0;          // 进入死区就完全停止纠正
} else {
  command.angular = std::clamp(turn_heading_gain_ * line_command.heading_error, ...);
}
```

这是**死区，不是收敛目标**。误差一落进 `alignment_tolerance_deg` 就把角速度指令置零，
不再往 0 收敛，因此残差是**穿过边界那一刻的余量**，冲进去多深就留多少。

而 `alignment_tolerance_deg` 原本是 **2.0**，与 §14.3 的验收阈值同一个数：控制器允许
自己停在验收线上，**余量结构性为零**。

用真值分解证实了这一点（大矩形竖向 19 段）：EKF 航向偏差只有 `−0.21°~+0.22°`，对齐
残差 `0.87°~1.78°`，误差几乎全部来自对齐，与定位无关。

### 修法

`alignment_tolerance_deg: 2.0 → 1.0`，留 2 倍余量。八个工况的航向误差变成
`0.723°~0.934°`，余量 53%~64%。

0.5 也实测干净（107 次整定，单次角速度符号翻转从未超过 1 次），但 1.0 不要求真机的
航向估计守住那么窄的死区，同时收敛压力小一半。

**没有引发振荡**：八个工况共 182 次整定，单次符号翻转最多 1 次——1 次是冲过头后的
正常单次回调，振荡需要 ≥2 次。代价是整定均值从 0.80 s 升到约 1.15 s，总耗时增加
4%~13%。

### 并行回归

`tools/run_coverage_regression.sh` 把八个工况分四路并行，11 分钟跑完（串行 70 分钟）。
每路需要 `ROS_DOMAIN_ID` **和** `GZ_PARTITION` 两层隔离——gz-transport 是独立于 DDS
的发现机制，缺了后者两路会互相驱动对方的机器人且不报错。实时因子 `0.85~0.94`，与
串行一致。

## 当前未决事项

### 1. WheelSlip 法向载荷局限

Gazebo WheelSlip 按配置的标称法向力缩放柔度，不随三个接触点的瞬时载荷变化。
这是已知模型保真度限制；第一阶段接受该限制，但真机参数解释时必须保留差异。
