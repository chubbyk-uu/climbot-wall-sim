# 墙面图像拼接：当前设计与门禁

更新：2026-08-28。本文定义当前离线拼接的职责、算法合同与未关闭门禁；已完成阶段的
逐轮设计、试验与历史数字见[拼接计划归档](archive/plans/MOSAIC_PLAN_2026-08-27.md)。
可执行命令、参数和目录字段以 [接口合同](INTERFACES.md) 为唯一来源，正式通过状态以
[验收矩阵](ACCEPTANCE.md) 为准。

## 目标与边界

将一份已封存的 G4 巡检归档转换为可追溯、米制且可检查的墙面母版：

```text
G4 原始归档 → 预处理 → processed-run → 位姿图 → hard-cut 母版 → 独立真值/原尺寸检查
```

- `climbot_inspection` 只负责未补偿原图与曝光位姿归档；
- `climbot_image_processing` 只负责校验、暗场/平场、可选去噪和去畸变；
- `climbot_mosaic` 只负责投影、匹配、位姿图和离线渲染；
- 三者均不反向依赖规划、控制或 Gazebo；原始 run 与 processed-run 永远不可改写；
- 第一版仅适用于已知平面 `wall, z=0`、固定焦距、灰度相机；不包含曲面、自动对焦、
  运动模糊补偿或在线增量拼接。

Gazebo 墙面 DDS、诊断 feature 清单与真值坐标只允许被**后验评价器**读取，绝不能进入候选
生成、局部匹配、位姿优化或渲染决策。

## 不可变数据与产物合同

输入预检、处理目录、各 CLI 的精确参数和字段见 [接口合同](INTERFACES.md)。本页只固定
跨阶段不变的关系：

| 项目 | 当前合同 |
| --- | --- |
| 帧身份 | 跨任务使用 `(source_run_id, frame_index)`，不可只用文件名 |
| 位姿初值 | 曝光时刻 EKF 相机位姿与冻结相机外参 |
| 墙面模型 | rectified 像素光线与 `z=0` 的交点；优化变量仅为 `δx, δy, δyaw` |
| 绝对先验 | 从归档 `6×6` 协方差显式提取 `x/y/yaw` 子空间，仅作加权依据 |
| 发布语义 | 输入只读；所有正式输出在独立不存在目录中原子发布 |
| 正式母版 | 0.25 mm/px、无损 tiled BigTIFF；预览不能用于测量或缺陷判断 |
| 渲染归属 | 硬切：每个墙面像素只保留源图边缘距离最大的照片，平局取稳定帧序较早者 |
| 公平比较 | pose-only 与 optimized 使用同一帧、网格、分辨率、插值与硬切归属；唯一变量为位姿 |

`work-dir`、特征缓存和临时 tile 是可再生的中间物，不是结果证据。正式输出须记录输入/标定
哈希、参数、提交、阶段耗时、峰值 PSS、输出 SHA-256、连通分量、拒绝边与低可信区域。

## 算法链

1. 严格验证 processed-run 的图像哈希、标签、去畸变内参、外参，以及位姿和协方差是否都是
   有限数值（不含 NaN／Inf）。
2. 将每帧像素投影为米制足迹；只从空间正面积相交的足迹建立匹配候选。
3. 在预测重叠区域执行特征、双向一致性、RANSAC 与固定尺度 SE(2) 局部约束；接受与拒绝
   都必须可追溯。
4. 以 EKF 绝对先验和视觉相对约束进行鲁棒稀疏位姿图优化；孤立帧保留先验并明确标识，
   不得伪装为视觉恢复。
5. 分块 hard-cut 渲染 pose-only 与 optimized 母版，同时输出覆盖次数、不确定度、差分、稀疏
   源图切换接缝和预览。
6. 仅在渲染完成后，以独立诊断墙真值计算绝对锚点、尺度、航向、局部残差，以及 hard-cut
   接缝的真值扣除灰度跳变；以同一母版、同一方向的 covered 非接缝邻接作为确定性基线，并导出
   原尺寸 truth / pose-only / optimized 检查 tile。

并行只能改变耗时：帧键、随机源、候选/边排序、接受边、优化问题和输出像素必须保持确定。
任何预检失败、worker 缺失、缓存损坏或写入失败均不得发布 completed 结果。

## 唯一未关闭门禁：P2-06

### 覆盖判据：冻结任务巡检域内 feature 零漏拍

判据域是**冻结任务的 `coverage_region` 多边形**，也就是
`coverage_p206_diagnostic_full_{horizontal,vertical}.yaml` 里声明、并由规划器随任务一起
发布的那块区域。选它的理由不是“它是物理可达域”，而是它正好是规划器承诺过的域：
`sampledCoverageRatio()` 就在这块区域内撒点，判断相机足迹盖没盖住。检查器验的因此是
规划器已经承诺过的同一块地方，域的定义不由运行检查器的人决定。

这块诊断墙上的三条 construction_seam 按设计贯穿整面墙（`0…8 m` 纵向两条、`0…10 m`
横向一条），`crack_decal_08` 与 `graffiti_decal_04` 也伸到 `x = 9.766 / 9.754 m`，
都在巡检域之外。域外像素不作要求。

**域外不作要求，不等于拍不到。** 相机足迹沿行进方向伸出机器人中心
`0.340 + 0.28125 / 2 = 0.481 m`、横向半宽 `0.250 m`，而巡检域四边距墙边 `0.55 m`，
所以足迹可以伸到巡检域外。此前本页和验收矩阵把全部域外像素写成“机器人不可达”，这个
结论没有依据；随后用 `coverage_region` 膨胀出的保守上包络又只能证明 `439,116` 个像素没有
落在上界之外，仍不能反向证明每个像素存在合法位姿。现在改为分别计算冻结计划的连续 SCAN
足迹，以及冻结 `motion_region` 内正反扫描方向的安全位姿相机包络。严格重跑得到：`32,504`
个域外缺口在当前计划 SCAN 足迹内、`406,612` 个不在；`439,116` 个全部位于安全位姿包络
内，包络外为 `0`。前一个结论现在由“安全中心位置 + 允许扫描朝向”构造位姿见证，不再从
上包络反推。

但**“包络外为 `0`”不是测量结果，是构造必然**：这些像素只能取自拼接域
`x[0.2286, 9.7709] y[0.3634, 7.6347]`，而它整幅落在安全位姿相机包络的并集
`x[0.0675, 9.9325] y[0.2981, 7.7019]` 之内，包络外根本没有像素可数。拼接域本身就是从
允许位姿拍到的帧张成的，所以这一项在本类数据上恒为 `0`，不能当作独立证据。有判别力的
是计划 SCAN 足迹那一组 `32,504 / 406,612`。域外不作要求始终只是**产品判据的选择**，
不是物理结论。

### 分层门禁

三层各管各的，不能互相替代：

| 层 | 判据 | 量测对象 | 由谁输出 |
| --- | --- | --- | --- |
| 规划可行性 | `minimum_nominal_coverage_ratio ≥ 0.95` | 巡检域**面积**的名义足迹覆盖率（`300×300` 采样） | `coverage_planner` |
| 采集前预检 | `all_intersecting_feature_samples_covered = true` | 按实际规划离散曝光采样的每个 **feature 声明几何** | `preflight_diagnostic_coverage` |
| 拼后验收 | 巡检域内 feature 像素零漏拍 | 实际 `coverage_count.tif` | `inspect_diagnostic_mosaic` |

第一层量的是面积，后两层量的是 feature 像素，测量量不同，所以 `0.95` 与 `100%`
不构成矛盾：规划允许边界上少量面积没被名义足迹盖到，并不等于允许漏掉 feature。
把第一层硬提到 `1.0` 有两个害处——采样栅格与浮点边界误差会脆弱地否掉理论可行的方案，
而“规划期就发现 feature 漏拍”这件事第二层已经在做，用的正是 100% 判据。

拆分由 `inspect_diagnostic_mosaic` 直接输出，写在
`diagnostic_inspection_summary.json` 里，**不是事后用脚本另算的**：门禁读
`all_inspection_region_feature_pixels_covered`，同时 `uncovered_outside_inspection_region`
逐 feature 列明，这样域外的缺口不会随时间悄悄变大而无人察觉。

巡检域本身也不是命令行给的。检查器沿
`mosaic manifest → processing_manifest.json → 归档 manifest.json → 冻结任务` 回溯，
每一环用 SHA-256 校验，从 `task.coverage_region` 取多边形、从 `task.detection_*` 取足迹。
这样“这次运行被拿什么来判”就不再是运行检查器的人能选的。

域外缺口同时按冻结计划的连续 SCAN 足迹和冻结 `motion_region` 的安全中心位姿包络分类。
前者区分当前计划是否本应扫到，后者区分是否存在安全中心位姿能拍到；两组计数都由评价器
直接输出。旧实现把 `coverage_region` 膨胀成保守上包络，像素落在上包络内并不能证明存在
位姿，因此不再用它支持“可以拍到”或“拍不到”的结论。

#### 已知系统性尺度偏置 `+21 ppm`

三组的尺度误差全为正。在拼接图上用 386 个 patch 密集测量得到各向同性 `+21 ± 2 ppm`
（三组分别 `+20 / +21 / +22`），在 10 m 墙上是 `0.21 mm`。测量方法经注入标定验证：注入
`0 ppm` 回收 `+0.09 / +0.28`，注入 `+50` 回收 `+48.2 / +49.6`——零偏置 `≤ 0.3 ppm`
且增益偏低，所以这个数只会被低估，不会被凭空造出。

逐段排除（均为实测）：`realistic` 注入的棱镜安装误差与 20 ms 时间戳偏置在 pose-only 上是
`13.37 mm` 的逐道锯齿，位姿图后降到 `0.078 mm`，且四个航向上均值为零，结构上产生不了尺度；
畸变反解等效 `−1.34 ppm`；320 个贴图块的盒子尺寸与 DDS 像素数偏差恰为 `0`；贴图外表面精确
落在碰撞面 `0.050000`；轮子接触穿透真值实测 `13 nm`（`0.046 ppm`）；Gazebo 自报内参精确为
`fx = 796.8`、`cx = 959.5`。单帧测量（225 帧，绕开位姿图与拼接装配）已含 `+12.6 ± 4.0 ppm`，
所以主因在位姿图上游的相机模型与两次重采样链。

**再往下无法细分**：要分辨 `20 ppm` 需要与墙面同量级的杠杆，而全系统里唯一横跨 9 m 的就是
被测的拼接图本身；单帧杠杆只有 `0.55…0.66 m`，同等定位精度下极限就是 `±4…8 ppm`。试过的三种
替代标尺（6 mm 凸出的网格线、无平场的理想图、合成重采样链）自身系统误差分别是
`100 / 313 / 1035 ppm`，都比信号大一到两个数量级。此偏置与任何随工况变化的量无关，
三次独立采集复现到 `±2 ppm`，因此作为已知常量记录并由门限包住，不做修正。

接缝统计只在 hard-cut 的源图切换邻接处计算；跳变扣除不可变墙面同位置梯度，off-seam
基线则在同一母版、相同方向的 covered 非接缝邻接上计算。此前的法向结构边位移 argmax
代理随搜索半径线性变化，无法区分本数据上的 pose-only 与 optimized，故不再作为正式结论。
这些数字和绝对数值都只有一组数据，不能冻结阈值。这些数字只有在“被拍平面与行驶平面不重合”
修复之后才成立，历史数据不可与之直接比较。真值评价器按 tile 流式读取，输出会记录本次进程
PSS 峰值；P2-06 本次实测为 `1.36 GB`，不把它与 P2-04 fusion 的 `4 GB` 配置预算混为一谈。

## 本轮查明的两处问题

### 已修复：被拍平面与行驶平面不重合

`3f422f5` 之前，诊断贴图块的外表面比墙面碰撞面高出 `1.25 mm`（`SURFACE_OFFSET_M = 0.001`
加上半个 `0.0005 m` 块厚）。轮子压在碰撞面上，相机却拍高出去的那一层，而拼接按碰撞面
（`wall_plane_z_m = 0`）投影，于是物距被高估 `0.46%`，整幅图带上 `+4566 ppm` 的各向同性
尺度误差——`9.5 m` 跨度上就是 `43 mm`。

它表现为位姿图优化无法消除的绝对偏差：图像之间对得很齐，只是整体尺度错了。判别依据是
各向同性——`fx = 842.08` 与 `fy = 922.39` 是两个独立标定量，不可能同时错同一个比例。

| 变体 | 尺度误差 | 绝对锚点 P95 | 局部残差 P95 |
| --- | --- | --- | --- |
| 修复前（同批图像） | `+4590 ppm` | `20.62 mm` | `0.921 mm` |
| 同批图像改投影到 `z = 1.25 mm` | `+25 ppm` | `1.20 mm` | `0.245 mm` |
| 修复后重采（干净路径） | `+17.4 ppm` | `1.67 mm` | `0.226 mm` |

修法是把贴图块外表面放到碰撞面上，并把 `wall_visual` 内缩让开 z-fighting，使轮子压的、
相机拍的、拼接投影的是同一个平面——真实墙面本来就是如此。拼接管线一行未改。

### 未闭合：一帧无法参与全局对齐

两次独立采集里，横向第 96 帧（`x = 4.459, y = 1.689`）的 SIFT 关键点都是 `0`，20 条候选
全部因 `mutual_matches = 0` 被拒，位姿图连通分量为 `[1339, 1]`。该处墙面纹理只有低频渐变。
它的位姿只能来自里程计，不参与全局优化。

实测影响可忽略：正下方的锚点 `repair_patch_02` 距其足迹中心 `0.162 m`，开启 `--use-clahe`
（该帧关键点 `0 → 479`，图变为完全连通，边误差降约 `30%`）后它只改善 `0.022 mm`，其余
锚点变化均小于 `0.09 mm`。hard-cut 按质量为每个像素挑源图，那一带被沿轨重叠和垂直扫描
重复覆盖，融合可以避开只有里程计定位的那一帧。

因此 `--use-clahe` 保留为开关而**不设为默认**：它使特征提取从 `32 s` 涨到 `218 s`，
换来的精度改善低于测量噪声。遇到大面积弱纹理墙面时它才是对的工具。

在此之前，只冻结输入可追溯、原子发布、硬切公平比较、无隐藏低可信区域、资源有界和
“optimized 不得劣于 pose-only”的关系门禁；不冻结任意最低改善比例或绝对毫米阈值。

## 风险控制

| 风险 | 当前控制 |
| --- | --- |
| 弱/重复纹理产生错误边 | 米制足迹限候选、双向匹配、RANSAC、鲁棒损失与拒绝原因持久化 |
| EKF 系统误差掩盖局部质量 | 相对接缝指标与独立真值锚点分别报告 |
| 大图超内存或磁盘 | 分块渲染、单写入器、显式内存预算、哈希与原子发布 |
| 多进程结果漂移 | 稳定排序/随机源/归约与跨 jobs 回归 |
| 开发数据过拟合 | 使用新的大工作区横、竖和联合数据，冻结参数后再评价 |
| 人工检查遗漏 | 每个实际相交 feature 导出原尺寸 tile，并把零覆盖显式列为失败边界 |
