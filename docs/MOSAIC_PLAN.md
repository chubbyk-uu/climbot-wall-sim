# 墙面图像拼接：当前设计与门禁

更新：2026-08-28。本文定义当前离线拼接的职责、算法合同与未关闭门禁；已完成阶段的
逐轮设计、试验与历史数字见[拼接计划归档](archive/plans/MOSAIC_PLAN_2026-08-27.md)。
可执行命令、参数和目录字段以 [接口合同](INTERFACES.md) 为唯一来源，正式通过状态以
[验收矩阵](ACCEPTANCE.md) 为准。

## 目标与边界

将一份已封存的 G4 巡检归档转换为可追溯、米制且可检查的墙面母版：

```text
G4 原始归档 → 预处理 → processed-run → 位姿图 → hard-cut 母版 → 独立真值/原尺寸检查
```

- `climbot_inspection` 只负责未补偿原图与曝光位姿归档；
- `climbot_image_processing` 只负责校验、暗场/平场、可选去噪和去畸变；
- `climbot_mosaic` 只负责投影、匹配、位姿图和离线渲染；
- 三者均不反向依赖规划、控制或 Gazebo；原始 run 与 processed-run 永远不可改写；
- 第一版仅适用于已知平面 `wall, z=0`、固定焦距、灰度相机；不包含曲面、自动对焦、
  运动模糊补偿或在线增量拼接。

Gazebo 墙面 DDS、诊断 feature 清单与真值坐标只允许被**后验评价器**读取，绝不能进入候选
生成、局部匹配、位姿优化或渲染决策。

## 不可变数据与产物合同

输入预检、处理目录、各 CLI 的精确参数和字段见 [接口合同](INTERFACES.md)。本页只固定
跨阶段不变的关系：

| 项目 | 当前合同 |
| --- | --- |
| 帧身份 | 跨任务使用 `(source_run_id, frame_index)`，不可只用文件名 |
| 位姿初值 | 曝光时刻 EKF 相机位姿与冻结相机外参 |
| 墙面模型 | rectified 像素光线与 `z=0` 的交点；优化变量仅为 `δx, δy, δyaw` |
| 绝对先验 | 从归档 `6×6` 协方差显式提取 `x/y/yaw` 子空间，仅作加权依据 |
| 发布语义 | 输入只读；所有正式输出在独立不存在目录中原子发布 |
| 正式母版 | 0.25 mm/px、无损 tiled BigTIFF；预览不能用于测量或缺陷判断 |
| 渲染归属 | 硬切：每个墙面像素只保留源图边缘距离最大的照片，平局取稳定帧序较早者 |
| 公平比较 | pose-only 与 optimized 使用同一帧、网格、分辨率、插值与硬切归属；唯一变量为位姿 |

`work-dir`、特征缓存和临时 tile 是可再生的中间物，不是结果证据。正式输出须记录输入/标定
哈希、参数、提交、阶段耗时、峰值 PSS、输出 SHA-256、连通分量、拒绝边与低可信区域。

## 算法链

1. 严格验证 processed-run 的图像哈希、标签、去畸变内参、外参，以及位姿和协方差是否都是
   有限数值（不含 NaN／Inf）。
2. 将每帧像素投影为米制足迹；只从空间正面积相交的足迹建立匹配候选。
3. 在预测重叠区域执行特征、双向一致性、RANSAC 与固定尺度 SE(2) 局部约束；接受与拒绝
   都必须可追溯。
4. 以 EKF 绝对先验和视觉相对约束进行鲁棒稀疏位姿图优化；孤立帧保留先验并明确标识，
   不得伪装为视觉恢复。
5. 分块 hard-cut 渲染 pose-only 与 optimized 母版，同时输出覆盖次数、不确定度、差分和预览。
6. 仅在渲染完成后，以独立诊断墙真值计算绝对锚点、尺度、航向与局部残差，并导出原尺寸
   truth / pose-only / optimized 检查 tile。

并行只能改变耗时：帧键、随机源、候选/边排序、接受边、优化问题和输出像素必须保持确定。
任何预检失败、worker 缺失、缓存损坏或写入失败均不得发布 completed 结果。

## 唯一未关闭门禁：P2-06

### 覆盖判据：机器人可达范围内零漏拍

判据只看机器人被允许行驶的矩形之内。这块诊断墙上的三条 construction_seam 按设计贯穿
整面墙（`0…8 m` 纵向两条、`0…10 m` 横向一条），`crack_decal_08` 与 `graffiti_decal_04`
也伸到 `x = 9.766 / 9.754 m`，都在绿色安全框之外；无论执行多完美，机器人都拍不到它们
伸出去的部分。要求“每个 declared 像素都被覆盖”对这块墙在物理上不可满足，把它当门禁只会
逼出一个永远为假的判定。

拆分由 `inspect_diagnostic_mosaic --drive-region-m` 直接输出，写在
`diagnostic_inspection_summary.json` 里，**不是事后用脚本另算的**：门禁读
`all_reachable_feature_pixels_covered`，同时 `uncovered_outside_drive_region` 逐 feature
列明，这样矩形外的缺口不会随时间悄悄变大而无人察觉。

## 本轮查明的两处问题

### 已修复：被拍平面与行驶平面不重合

`3f422f5` 之前，诊断贴图块的外表面比墙面碰撞面高出 `1.25 mm`（`SURFACE_OFFSET_M = 0.001`
加上半个 `0.0005 m` 块厚）。轮子压在碰撞面上，相机却拍高出去的那一层，而拼接按碰撞面
（`wall_plane_z_m = 0`）投影，于是物距被高估 `0.46%`，整幅图带上 `+4566 ppm` 的各向同性
尺度误差——`9.5 m` 跨度上就是 `43 mm`。

它表现为位姿图优化无法消除的绝对偏差：图像之间对得很齐，只是整体尺度错了。判别依据是
各向同性——`fx = 842.08` 与 `fy = 922.39` 是两个独立标定量，不可能同时错同一个比例。

| 变体 | 尺度误差 | 绝对锚点 P95 | 局部残差 P95 |
| --- | --- | --- | --- |
| 修复前（同批图像） | `+4590 ppm` | `20.62 mm` | `0.921 mm` |
| 同批图像改投影到 `z = 1.25 mm` | `+25 ppm` | `1.20 mm` | `0.245 mm` |
| 修复后重采（干净路径） | `+17.4 ppm` | `1.67 mm` | `0.226 mm` |

修法是把贴图块外表面放到碰撞面上，并把 `wall_visual` 内缩让开 z-fighting，使轮子压的、
相机拍的、拼接投影的是同一个平面——真实墙面本来就是如此。拼接管线一行未改。

### 未闭合：一帧无法参与全局对齐

两次独立采集里，横向第 96 帧（`x = 4.459, y = 1.689`）的 SIFT 关键点都是 `0`，20 条候选
全部因 `mutual_matches = 0` 被拒，位姿图连通分量为 `[1339, 1]`。该处墙面纹理只有低频渐变。
它的位姿只能来自里程计，不参与全局优化。

实测影响可忽略：正下方的锚点 `repair_patch_02` 距其足迹中心 `0.162 m`，开启 `--use-clahe`
（该帧关键点 `0 → 479`，图变为完全连通，边误差降约 `30%`）后它只改善 `0.022 mm`，其余
锚点变化均小于 `0.09 mm`。hard-cut 按质量为每个像素挑源图，那一带被沿轨重叠和垂直扫描
重复覆盖，融合可以避开只有里程计定位的那一帧。

因此 `--use-clahe` 保留为开关而**不设为默认**：它使特征提取从 `32 s` 涨到 `218 s`，
换来的精度改善低于测量噪声。遇到大面积弱纹理墙面时它才是对的工具。

在此之前，只冻结输入可追溯、原子发布、硬切公平比较、无隐藏低可信区域、资源有界和
“optimized 不得劣于 pose-only”的关系门禁；不冻结任意最低改善比例或绝对毫米阈值。

## 风险控制

| 风险 | 当前控制 |
| --- | --- |
| 弱/重复纹理产生错误边 | 米制足迹限候选、双向匹配、RANSAC、鲁棒损失与拒绝原因持久化 |
| EKF 系统误差掩盖局部质量 | 相对接缝指标与独立真值锚点分别报告 |
| 大图超内存或磁盘 | 分块渲染、单写入器、显式内存预算、哈希与原子发布 |
| 多进程结果漂移 | 稳定排序/随机源/归约与跨 jobs 回归 |
| 开发数据过拟合 | 使用新的大工作区横、竖和联合数据，冻结参数后再评价 |
| 人工检查遗漏 | 每个实际相交 feature 导出原尺寸 tile，并把零覆盖显式列为失败边界 |
