# 墙面图像预处理与拼接实施计划

更新日期：2026-08-26。

本文是 `climbot_image_processing` 后续优化和新包 `climbot_mosaic` 的专项设计、
实施与验收计划。它落实 [PROJECT_GUIDE.md](../PROJECT_GUIDE.md) §18.7 已确定的离线数据
边界，但不把尚未实测的拼接性能数字提前写成正式门限。当前状态是 **P2.1 并行预处理和 P2.2
拼接输入预检已完成，拼接性能基线尚未建立**；后续只有完成横向开发集、竖向独立验证集和联合数据集实测后，
才能冻结最终数值验收线。

## 1. 目标与范围

本阶段要把一次已封存的墙面巡检任务转换为可量测、可追溯的米制墙面拼接图：

```text
G4 原始归档
    ↓ 完整性校验
climbot_image_processing
    ↓ 暗场／平场、可选去噪、去畸变
processed-run
    ↓
climbot_mosaic
    ├─ 初始墙面投影
    ├─ 重叠候选图
    ├─ 特征匹配与外点剔除
    ├─ 带绝对先验的鲁棒全局位姿优化
    ├─ 分块融合
    └─ 母版、预览、优化位姿和质量报告
```

边界保持如下：

- `climbot_inspection` 只采集未补偿、未去畸变的原始灰度图和曝光位姿标签；
- `climbot_image_processing` 只做离线校验、光照补偿、可选去噪和畸变校正；
- `climbot_mosaic` 只做墙面投影、重叠匹配、全局优化和融合；
- 两个离线包不得成为规划器、控制器、Gazebo 或在线采集的依赖；
- 原始 G4 run 和 processed-run 都视为不可变输入，任何后续结果写入新的独立目录；
- 第一版只处理已知平面墙体和固定焦距工业灰度相机，不在同一阶段扩展曲面、运动模糊、
  自动对焦或在线增量拼接。

## 2. 当前正式开发数据

2026-08-26 已用 `0.25 mm/texel` 墙面贴图重新采集两组数据：

| 数据集 | 机器人可走区 | 扫描航向 | 扫描线 | 原始图像 | 已测照片足迹覆盖 |
| --- | ---: | --- | ---: | ---: | ---: |
| `inspection-dataset-horizontal-025mm-20260826` | 约 `6.0 × 4.1 m` | 左右交替，受重力补偿产生向上偏航 | 10 | 270 | `96.762%` |
| `inspection-dataset-vertical-025mm-20260826` | 约 `4.1 × 6.0 m` | 上下交替 | 10 | 270 | `97.278%` |

两组归档均为 `completed`，并满足 `expected_images == saved_images == 270`、零失败图、
图片与 metadata 一一对应。G2 观察器测得曝光相机位姿相对 Gazebo 真值的最大误差分别约
`4.25 mm` 和 `4.46 mm`。这些是已有证据，不代表拼接后的最终门限。

数据使用顺序固定为：

1. 横向 270 张作为算法开发集和首次性能基线；
2. 参数冻结后，竖向 270 张作为不再调参的独立验证集；
3. 两组 540 张联合拼接作为跨任务、跨航向的最终泛化验证；
4. 若查看竖向结果后必须改变算法或参数，竖向不再算独立验证，必须重新确定验证数据。

## 3. 目录接口

### 3.1 预处理输入与输出

沿用已实现的单向目录接口：

```bash
ros2 run climbot_image_processing process_inspection_archive \
  --input-run <绝对的 completed G4 run> \
  --output-dir <绝对的、不存在的 processed-run> \
  [--flat-field-file <gain.npz>] \
  [--dark-frame <dark.png>] \
  [--denoise none|median3] \
  [--jobs auto] [--memory-budget-gb <GiB>]
```

本批新数据默认使用当前弱光 LED 平场文件、无暗场、`denoise=none`，避免在原图已经偏软的
情况下进一步损失细节。去畸变后的内参、冻结外参、处理操作和输入输出 SHA-256 继续写入
processed-run。

### 3.2 拼接命令

计划新增：

```bash
ros2 run climbot_mosaic build_wall_mosaic \
  --input-run <绝对的 processed-run> \
  [--input-run <第二个 processed-run>] \
  --output-dir <绝对的、不存在的 mosaic-run> \
  --resolution-mm-per-pixel 0.25 \
  [--jobs auto] [--memory-budget-gb <GiB>] \
  [--work-dir <可复用缓存目录>]
```

多个 processed-run 中可能存在相同的 `000000.png`，内部帧标识必须使用
`(source_run_id, frame_index)`，不能只使用文件名。正式结果仅在全部阶段成功后原子发布；
计算缓存与正式输出分离，缓存不作为完成证据。

### 3.3 计划输出

```text
mosaic-run/
├── mosaic_manifest.json
├── mosaic_preview.jpg
├── mosaic_pose_only.tif
├── mosaic_optimized.tif
├── mosaic_comparison.jpg
├── mosaic_difference.tif
├── coverage_count.tif
├── uncertainty.tif
├── poses/
│   ├── initial_poses.json
│   └── optimized_poses.json
├── graph/
│   ├── candidate_edges.json
│   ├── accepted_edges.json
│   └── rejected_edges.json
└── diagnostics/
    ├── quality_report.json
    └── selected_match_previews/
```

`mosaic_manifest.json` 至少记录输入 manifest 哈希、相机标定哈希、帧数、算法参数、特征与
匹配配置、优化配置、墙面范围、米制分辨率、输出文件 SHA-256、软件提交、各阶段耗时和峰值
内存。质量报告必须包含连通分量、被拒匹配、优化前后残差和低可信区域，不能只输出一张图。
`mosaic_pose_only.tif` 与 `mosaic_optimized.tif` 必须使用完全相同的输入帧、墙面范围、米制
分辨率、像素融合和灰度输出规则，唯一变量是照片位姿是否经过全局优化；并排预览和差分图
用于直观看接缝、重影与局部错位是否改善，质量报告同时给出两者的同口径指标。

## 4. 坐标与几何模型

processed-run 中每张图包含去畸变内参、相机安装外参快照、曝光时刻相机六自由度位姿、
`6 × 6` 协方差和冻结扫描参考。第一版利用已知墙平面，在墙面坐标系中求像素到 `z=0`
平面的单应变换：

- 相机位姿标签给出米制绝对初值；
- 去畸变后的 `K` 和固定相机高度确定像素尺度；
- 每张图得到墙面上的米制四边形足迹；
- 从六自由度协方差通过明确 Jacobian 提取墙面 `x/y/yaw` 先验协方差；
- 协方差只能作为加权依据，不能通过任意放大协方差掩盖残差；
- 第一版优化变量是每张图的平面修正 `δx、δy、δyaw`，尺度不是自由变量。

这一区分两种精度：局部相对精度决定接缝和双影；墙面绝对精度决定整幅图是否处于正确
米制坐标。两者必须分别报告，不能用“看起来无缝”替代绝对位置评价。

## 5. 图像尺寸、分辨率与压缩

相机当前有效墙面采样约为 `0.286 mm/px`，贴图源为 `0.25 mm/texel`。正式母版选择
`0.25 mm/px` 会略微过采样相机，但不会主动丢失已采集细节。近似尺寸为：

| 范围 | `0.25 mm/px` 像素尺寸 | 单通道 `mono8` 未压缩大小 |
| --- | ---: | ---: |
| 横向约 `6.0 × 4.1 m` | `24000 × 16400` | `393.6 MB` |
| 竖向约 `4.1 × 6.0 m` | `16400 × 24000` | `393.6 MB` |
| 横竖联合约 `6.0 × 6.0 m` 包围范围 | `24000 × 24000` | `576 MB` |
| 整面 `10 × 8 m` 墙 | `40000 × 32000` | `1.28 GB` |

最终精确边界由优化后的照片足迹并集决定，上表只用于资源设计。输出策略为：

- 正式母版：分块 BigTIFF、单通道 8 位、`1024 × 1024` 或 `2048 × 2048` tile；
- 默认使用 Zstd 无损压缩，不可用时回退 Deflate；
- 混凝土纹理和噪声不容易高度压缩，预计单任务母版约 `200～350 MB`、联合母版约
  `300～550 MB`，这里只是容量规划，必须由首次实测替换；
- 快速预览：`1.0 mm/px`、JPEG 质量 `90～95`，不得用于测量和缺陷识别；
- 覆盖次数与不确定度图默认使用较低分辨率和无损压缩；
- 正式缺陷分析不得用 JPEG 代替无损母版。

## 6. 预处理并行与效率设计

540 张照片之间的平场、去畸变、编码和哈希互相独立。现有串行链计划按以下原则改造：

1. 主进程只读取和校验一次内外参；
2. 使用 `cv2.initUndistortRectifyMap` 预计算一次 remap，不能每张图重复求映射；
3. 平场 gain 和 remap 使用只读共享内存、内存映射或 Linux fork 写时复制；
4. 多进程工作者执行读取、暗场／平场、`cv2.remap`、PNG 编码和 SHA-256；
5. 每个工作者把 OpenCV 内部线程限制为 1，避免进程数乘内部线程数造成过量并行；
6. 使用有界队列和内存预算限制在途图片数量；
7. 主进程按帧号稳定排序并写 manifest，保证不同 `--jobs` 下业务结果一致；
8. 工作者异常必须使整次处理失败，不能只少写一张图继续发布。

`--jobs=auto` 必须同时参考可用 CPU 和内存预算。首次在当前 24 线程主机上以 `6～8`
个工作进程建立基线，此数值不是跨机器默认保证。

## 7. 拼接算法与并行设计

### 7.1 初始投影

完整验证 processed-run 后，计算每张图片的米制单应矩阵、墙面足迹、初始位姿和初始覆盖。
先生成仅依赖曝光 EKF 位姿的初始预览，作为视觉优化前基线。

### 7.2 重叠候选图

不能对 270 或 540 张图做全组合匹配。候选边从初始米制足迹相交推导，覆盖：

- 同一扫描线的前后重叠；
- 相邻扫描线的横向重叠；
- 非时间相邻但空间相交的闭环候选；
- 联合拼接时横向和竖向任务之间的跨任务重叠。

候选筛选只减少计算量，不能作为最终匹配证据。候选图、拒绝原因和连通分量必须持久化。

### 7.3 特征与局部匹配

第一版优先使用 SIFT，以适应低对比度、重复纹理和 180° 反向拍摄。仅在预测重叠区域提取
和匹配特征；可以对“特征检测副本”做 CLAHE，但正式融合像素不得因此被改写。局部流程为：

```text
重叠 ROI → SIFT → KNN ratio test → 双向一致性 → RANSAC → 米制相对约束
```

每张图片的特征提取可多进程并行，每条候选边的匹配和 RANSAC 也可独立并行。RANSAC
随机种子由稳定的帧对键派生，边结果最终按帧键排序。特征和匹配结果必须缓存，修改融合
参数时不应重新计算它们。

### 7.4 全局优化

优化目标为：

```text
加权总残差 = EKF 曝光位姿绝对先验残差 + 重叠图像相对约束残差
```

使用固定规范自由度和可追溯的鲁棒损失，第一轮优化后依据残差重新检查边，再做第二轮
优化。当前实测采用线性预解建立一致初值，再使用平滑 `soft_l1`；Huber／Cauchy 在大部分
初始残差同时进入降权区时收敛明显较差，因此不作为当前默认。全局优化是一个小型稀疏问题，
不做盲目的 Python 多进程拆分；应使用稀疏
Jacobian 和底层线性代数并行。若 SE(2) 位姿图的实测残差和局部形变不能满足后续冻结的
门限，再单独评估基于全部内点的二维束调整，不在第一版提前引入。

### 7.5 分块融合

不得创建整幅强度、权重和不确定度的多层浮点画布。渲染按 tile 独立执行：

```text
取一个 tile
→ 查询与它相交的优化后照片
→ 按稳定顺序投影和加权
→ 生成灰度、覆盖次数与置信度
→ 压缩写盘
→ 释放临时数组
```

tile 计算可多进程并行，但一个有序写入器负责正式 TIFF，避免多个进程并发修改同一文件。
每个工作者使用有界 LRU 图片缓存；并行 tile 数由内存预算限制，而不是只由 CPU 数决定。
第一版使用边缘羽化和位姿置信度权重，不使用可能掩盖墙面缺陷的强局部亮度拉伸。

## 8. 缓存、恢复与确定性

计划的工作缓存为：

```text
work-dir/
├── features/
├── matches/
├── graph.json
└── cache_manifest.json
```

缓存键至少包含 processed image SHA-256、标定哈希、算法及参数、候选边规则和软件版本。
缓存不进 Git，也不等于正式结果。要求：

- 输入或相关参数变化时旧缓存必须失效；
- 修改纯融合参数时可复用特征、匹配和优化结果；
- 中断后可从最近完成阶段继续；
- 任务排序、随机种子、边排序和 tile 内图片归约顺序稳定；
- 不同 `--jobs` 不得改变图结构、接受边和优化语义；
- 并行异常、缺失 worker 结果或缓存损坏必须失败并说明，不能伪装成成功命中。

  `1.698 mm`；位置修正中位 `9.06 mm`、P95 `15.01 mm`，航向修正 P95 `0.158°`；
- 视觉图连通分量为 `[539, 1]`，孤立的竖向第 134 帧只由 EKF 先验约束，必须在后续
  不确定度图中显式保留，不允许伪装成有视觉约束；
- 原子输出初始位姿、优化位姿、保留边编号、优化前后残差、连通分量与 Jacobian 对角后验
  标准差近似；已增加已知修正恢复、确定性和非法配置测试。

### P2.6：并行分块融合与压缩输出

- 实现内存预算、tile 查询、并行融合和单写入器；
- 分别输出只用 EKF 曝光位姿的无损母版和全局优化后的无损母版，并输出同范围并排预览、
  差分图、覆盖次数和不确定度；除位姿外两条渲染链的输入及融合参数必须完全相同；
- 记录输出大小、耗时、峰值内存和缓存命中率。

### P2.7：三组正式实测与门限冻结

1. 横向开发集建立完整基线并由人工查看关键区域；
2. 根据物理分辨率、分布统计和可接受视觉效果形成候选门限；
3. 冻结算法和参数；
4. 竖向独立验证，不根据结果继续调参；
5. 运行横向加竖向 540 张联合拼接；
6. 以三次结果中较差的合理分布加工程裕量，冻结正式门限；

## 10. 验收制定原则

### 10.1 现在可以冻结的硬要求

以下要求不依赖墙面是否容易匹配，可以立即作为正式正确性门禁：

| ID | 要求 |
| --- | --- |
| P2-C01 | 输入 run、图片、metadata、标定和 SHA-256 全部校验，原输入始终不变 |
| P2-C02 | 每张输入必须进入结果、被明确拒绝或标为低可信；不得静默丢帧 |
| P2-C03 | 多 run 帧标识唯一，坐标、协方差、单应矩阵和权重必须有限且物理合法 |
| P2-C04 | 优化不收敛、图不满足配置要求、worker 丢失或写入失败时不得发布 completed 结果 |
| P2-C05 | 输出可追溯到输入哈希、标定、参数和软件提交，并包含失败与低可信区域 |
| P2-C06 | 正式母版保持米制比例、灰度无损；预览图不得替代母版 |
| P2-C07 | 内存受显式预算约束，不得建立整幅多层浮点画布 |
| P2-C08 | 不同并发数不得改变候选图、接受边、帧去留和优化问题定义 |
| P2-C09 | 仿真真值只允许验收器读取，拼接算法不得用真实贴图或 Gazebo 真值优化自身 |
| P2-C10 | pose-only 与 optimized 母版必须同输入、同范围、同分辨率、同融合，仅位姿不同 |

### 10.2 首次实现必须统计但暂不设门限的指标

| 范围 | 必须输出的指标 |
| --- | --- |
| 数据 | 输入、处理、参与视觉约束、仅先验、拒绝和最终渲染帧数 |
| 图结构 | 候选／接受／拒绝边数、连通分量、每张图度数、同轨／跨轨／跨任务边分布 |
| 特征 | 关键点、原始匹配、双向匹配、RANSAC 内点、内点率及失败原因分布 |
| 几何 | 优化前后像素和毫米残差、位姿修正、尺度误差、航向误差和后验不确定度 |
| 视觉 | 重叠区灰度差、接缝梯度、双影位移和人工 100% 缩放检查结果 |
| 覆盖 | 照片足迹并集、最终有效面积、内部空洞和相对 G2 口径差异 |
| 资源 | 各阶段墙钟时间、CPU 利用率、峰值内存、读写量、缓存大小与命中率、输出大小 |

### 10.3 当前不得写成硬门限的建议数字

讨论中出现过局部错位 `1 mm`、绝对位置 `5 mm`、重投影 `1/3 px`、灰度差 `5/12 DN`、
单边 `30` 个内点、跨轨 `3` 条边、跨任务 `20` 条边、残差降低 `30%`、足迹保留
`99.5%`、单任务 `30 min` 和联合 `60 min` 等建议。这些数值目前都缺少本项目拼接实测，
只可作为基线分析时的参考列，不能决定第一版通过或失败。

例如，若冻结算法后横向和竖向的实际 95% 局部错位分别为 `1.4 mm` 和 `1.8 mm`，且人工
检查确认没有可见双影，则正式门限应从实际分布、像素采样和工程裕量推导，而不是坚持事前
假设的 `1 mm`。反之，若实测远优于建议，也不应无依据放宽。

### 10.4 仿真绝对真值验收器

Gazebo 使用的墙面贴图、块清单和米制放置位置已知，可以建立独立验收器：

- 拼接算法只读取 processed-run、曝光 EKF 位姿和标定；
- 验收器额外读取墙面真实纹理及其米制坐标；
- 验收器比较拼接图和真实墙面图，统计整体偏移、局部形变、尺度、航向和有效区域；
- 真值不得参与特征筛选、位姿优化或融合；
- 绝对位置与视觉接缝分别评价，避免一项掩盖另一项。

真值评价方法本身先用合成已知变换验证；只有评价器误差显著低于被测误差后，其结果才能
用于冻结绝对门限。

### 10.5 最终正式验收结构

基线完成后，正式验收矩阵至少覆盖：

1. 数据完整性与输入不可变；
2. 单应投影和米制坐标正确；
3. 视觉约束图连通性；
4. 局部匹配和优化后相对误差；
5. 相对 Gazebo 真值的绝对位置、尺度和航向误差；
6. 接缝、双影、亮暗拼块和缺陷细节保持；
7. 相机已采集足迹的保留和无解释空洞；
8. 低可信与不确定区域如实输出；
9. 横向、竖向、联合三组泛化结果；
10. 并行一致性、资源上限、缓存恢复和输出完整性。

最终通过不能只依赖人工观感，也不能只依赖一个总残差。必须同时具备可接受的整体预览、
100% 局部检查、客观几何指标、真值指标和可追溯质量报告。

## 11. 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| 混凝土重复或弱纹理导致错误匹配 | 初始足迹限制候选、双向匹配、RANSAC、鲁棒损失和跨轨分布检查 |
| 横向照片带向上偏航，竖向照片上下反向 | 完整使用曝光相机姿态和旋转不变特征，不按扫描方向写特殊拼接分支 |
| EKF 绝对先验保守或存在相关误差 | 使用完整协方差和鲁棒先验，分别报告相对与绝对精度 |
| 平场后仍有低频亮度差 | 首先量化，不立即用强曝光补偿掩盖；必要时增加受限低频增益模型 |
| 全分辨率输出耗内存和磁盘 | tile 渲染、无损压缩、低分辨率辅助图、显式内存与磁盘预检 |
| 并行造成非确定性或伪成功 | 稳定种子／排序／归约、单写入器、worker 结果计数和跨 jobs 回归 |
| 用同一数据反复调参造成过拟合 | 横向开发、竖向冻结验证、联合最终验证；调参后重置验证资格 |

## 12. 完成定义

本阶段只有在以下事项全部完成后才能称为完成：

- 并行预处理链和 `climbot_mosaic` 已实现并通过单元、节点外离线和合成测试；

- 横向开发、竖向独立验证和 540 张联合拼接均产生可查看母版及质量报告；

- 文档、CI、状态和验收矩阵同步收口。
