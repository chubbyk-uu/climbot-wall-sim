## 配置与方法

逐案例先 legacy、后 vacuum_chassis，单实例串行；真实 WSL Gazebo GUI、私有 Mesa 25.2.8、
共享 D3D12 GUI 后端。server／GUI 均有实际四库映射与哈希，未混入系统 Gallium。
控制采用标准 DiffDrive／ROS 看门狗链路、原 `time` 控制及原门槛；不改变风机曲线、接触、
轮胎或补偿系数。两种机械结构分别读到真实几何，新轮距 0.435 m、半径 0.0475 m。
目标实时率 1、物理步 1 ms、ROS clock 500 Hz；预热后按接收端单调墙钟与消息源仿真时间
计算完整窗口和每 10 墙钟秒斜率。测量时没有运行完整套件、构建、拼接或其他仿真实例。

所有初始桌面截图已打开核对，另有新模型运动中截图显示位姿变化；复核记录在上级
`gui_visual_checks.json`。逐组传感器／轮子／相机 TF 连通，raw IMU、wall IMU、定位、
真值、关节、clock 均收到数据；新模型还记录压力真值与传感器，支撑已撤除，无启动／运行错误。

## 溯源、复现与边界

source_manifest.json 中已跟踪源码按历史源提交逐一重算 SHA-256，全部一致，数量见 source_audit.json。
原清单还包含被 Git 忽略的 pytest 缓存摘要；原清单保留，审计明确将这些非运行输入的缓存
元数据单列，不把它们冒称为可从 Git 重建的源码。后续清单改用 Git 跟踪文件列表。
运行二进制哈希和实际进程匹配在上级 installed_binaries.json；压力插件与 S5 哈希相同。
完整诊断日志在 /tmp，各组只保存唯一日志名；CSV／JSONL 不重采样，采用 gzip 保存。

检出源提交并构建、source ROS／工作区后，运行
`python3 tools/run_vacuum_gui_regression.py --output <新的绝对目录>`。
额外原生工具的原始字节在 replay/，按其原目录约定放入 /tmp 后在干净重建目录运行；
不能覆盖本档案。每个案例有解析后的实际源配置、命令／路径轨迹和独立观察结果。

本批没有出现观察器的收尾误报；另一个确定性软件测试已确认其正常退出信号路径存在竞态，
修复与红绿证据另在上级 observer_shutdown_regression.json 记录。该工具问题不代表 GUI
真实崩溃，也没有被当作压力、接触或物理模型失败。后续工具修复不得改写本批 7f92e74 溯源。
