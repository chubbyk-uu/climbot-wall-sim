# 失压跌落后的异常状态可观测性

2026-10-18。实际 GUI 全停演示暴露：裙边压缩超限后，插件锁存 runtime failure 并停止施力，
但真值话题也停止发布；外部只剩下异常前的 `runtime_failed=0`。不改变裙边限值或增加吸力。

现在异常后继续按原频率发布故障、当前仿真时间、风机命令和一阶转速，力字段清零，
`last_valid_time_s` 标出最后成功求解时间；腔压等求解快照无效，压力传感器不再采样／送达。
reset 清除故障后恢复正常启动。全步状态校验移至施力之前，避免已知几何域异常产生半步施力。

受控 A/B 仅切换 `VacuumSystem` 的旧／新实现，其余为同一个当前 IO、核心和新质量配置。
三台风机在 1.2 s 关闭，先观察真实重力下滑，再在 2.2 s 把机器人放到远离墙面的明确不支持
姿态（x=2 m，z=2 m，rpy=0），确定性触发方向域异常。2.5 s 重新启用风机，3.2 s reset；
两个代次均验证。此姿态注入只在独立 probe 显式配置时启用，正常验收不会注入。

- 旧实现稳定失败于异常后 `vac_time_s != sim_time_s`；实际传输话题没有故障消息。
- 新实现通过：故障时间持续推进、实际传输话题有多个失效快照、施力与支撑均为零，
  重新启用风机只恢复转速；故障不自动清除。压力采样时间保持不变，reset 之后正常启动。

精确统计、原始时序、实际话题消息及源码／日志哈希见 [summary.json](summary.json)。
回归入口为 `test_all_fans_off_failure_remains_observable_and_reset_recovers`。
这修复的是故障可观测性，不宣称模型能连续模拟脱墙、翻转和撞地过程中的腔体与裙边物理。

试验边界如实保留：第一轮仅靠自由落地未必触发异常，新碰撞代理能使模型在另一姿态落稳；
因此改为显式不支持姿态。一次靠墙姿态注入造成大量碰撞并被终止，之后将注入点移到远处，
不把这两次夹具诊断当作产品红绿对照。安装库与构建库是同一文件，初版对照脚本复制时报错，
finally 已恢复新源码并重建；正式 v2 对照检查同文件后跳过复制。完整日志均留在 `/tmp`。
